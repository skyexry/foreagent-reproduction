# Does execution memory change the choice?

Registered 2026-11-10 before computing switch counts. Prior knowledge includes the corpus pilot and the chronology audit (130 of 136 batches with three or more history nodes). Population: the 136 archived sibling batches pinned in chronological-memory-v1/run-001/batches.jsonl. This is a decision and coverage audit. Candidate outcomes play no role in selection.

1. Reuse the previously frozen chronological memory score for each sibling, based on up to ten earlier same-run validation results, word TF–IDF and the three nearest historical programs. Below three historical nodes the selector returns the baseline unchanged. A testable prediction is that memory alters some choices even among siblings that share the same parent. If coverage permits, measure this against reconstructed C0.
2. For the previously specified fusion B, the judge ranks by C0 top-group membership, accepted win fraction (neutral 1/2 at zero accepted degree), then number of distinct accepted opponents. Retain each distinct accepted edge once. Rank both streams with average ranks over ties, then select the lowest combined rank sum. Require the historical C0 top group and its accepted edge graph to be identified, or prove the decision invariant across all feasible alternatives. Batches with insufficient history have a zero switch by definition even if the C0 identity is unknown.
3. Compare complete top sets. Also operationalize *one choice* using a single predeclared shared priority order per batch, applied to both top sets. Order candidates by ascending SHA-256 digest of the UTF-8 string formed by joining the four fields (literal seed c0-memory-switch-v1/20261110, run, decimal first_log_line, full candidate ID) with a vertical bar. Report realized switches, disjoint sets (always switch), equal sets (never switch), overlapping unequal sets (tie-sensitive), and exact expected count under a shared random order. The latter uses P(switch) = 1 - |intersection|/|union|. A choice here selects one code for prospective execution. The original historical execution layer allowed several codes, probability skips and a forced fallback.
4. Report counts on all 136 and on eligible batches. In unresolved rows leave true switch status open unless invariance follows from the designated fallback and retained evidence. Report the resulting all-batch identification interval.
5. For all batches independently compute the following documented proxy using original display ranks from the journal. Its baseline top group consists of nodes at the lowest logged display rank. Its judge ordering is the full historical display ranking (ties kept). Combine that order and the same memory ranks with the same weights and shared tie rule. This proxy changes both the judge inputs and the judge ordering definition relative to C0 fusion B. It measures how frequently memory *could* alter a choice given this observed ordering. Report how often the predicted memory values vary among the ten siblings. Equal or distinct scores alone give no outcome information. There are no paid calls, new executions or threshold searches. Stop after this census and consistency checks.
