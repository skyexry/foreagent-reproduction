# 80 个改选对的预测覆盖与 GPU 预算

在此前准确指出两份代码的 80 个改选对中，**0 对能直接用已有预测比较官方分数**。32 对只有一边留有预测（C0 28、记忆融合 4），48 对两边都缺。我们在 CPU 上重算了全部 32 份。29 份作者运行的结果与节点旁的五位小数官方评分全部吻合，其余 3 份与本项目先前按 ID 对齐的独立评分吻合。

| 任务 | 改选对 | 仅 C0 有预测 | 仅记忆有预测 | 双方均缺 | 两边可比 |
|---|---:|---:|---:|---:|---:|
| Aerial Cactus | 8 | 3 | 0 | 5 | 0 |
| Histopathology | 1 | 0 | 0 | 1 | 0 |
| Stanford RNA | 32 | 11 | 1 | 20 | 0 |
| Statoil Iceberg | 31 | 11 | 2 | 18 | 0 |
| Ventilator | 8 | 3 | 1 | 4 | 0 |
| **合计** | **80** | **28** | **4** | **48** | **0** |

预测和旧验证记录是两类文件。我们从 15 次作者运行的完整目录（含各次保存点）和本项目标准 Stanford 运行出发，按任务、journal 节点、代码全文指纹和实际执行状态关联逐节点提交。另以内容哈希查找同任务中相同代码留下的预测并核对共享目录的最终提交，所有共享预测都能追溯到已有节点文件。本机独立检查还覆盖 3 个观察者快照和 4 个已压缩的检查点。160 个候选中，120 个当时标为跳过，另 8 个执行后缺少合格的逐节点预测。各任务以作者的私有划分、固定评分器原样计算；列名、样本 ID 和顺序得到核对。32 份单边分数来自原策略所选的样本，不宜比较两列均值来推断融合收益。

## 一个小规模配对实验要多久

选择 Stanford 和 Statoil，各 3 对，分别取自 3 次作者运行。每一对的两种方法首选集合没有交集。优先利用已有预测的样本、以及独立按批次抽取的样本，都在[配对名单和预算](pilot.json)中。挑选依据为任务、运行、分歧、文件可用性与固定哈希顺序。所选批次代表这两个任务中的明确分歧；五任务整体收益需要另外抽样。

| 方案 | 新执行 | 按历史单次中位数折算 | 按历史单次上四分位数折算 | 执行上限 | 含 30 分钟准备的预算 |
|---|---:|---:|---:|---:|---:|
| 复用 6 个已评分端点，各补跑缺的一边 | 6 份 | 0.24 卡时 | 0.45 卡时 | 2 卡时 | 2.5 卡时 |
| 在同一硬件、环境和种子下重新运行双方 | 12 份 | 0.47 卡时 | 0.90 卡时 | 4 卡时 | 4.5 卡时 |

估算使用实际同父候选从启动到返回的耗时。Stanford 有 46 份成功记录，中位数 124 秒，上四分位数 265 秒；Statoil 有 52 份，中位数 159 秒，上四分位数 272 秒。失败和超时分别记账，详见原始日志。6 个优先复用的对照端点在历史上合计运行 **0.41 小时**。表中卡时按独占单 GPU 机器、顺序运行计算，包含程序中的数据读取和 CPU 阶段。机器准备另预留 30 分钟；预下载数据并缓存镜像可减少租机等待。作者历史运行的硬件速度、未运行候选的训练长度、初始化、失败重试会影响实际用时。

建议单份执行限时为 Stanford 30 分钟、Statoil 10 分钟，超时或无效提交记录为失败。第一种做法能用最少新增执行获得六个有分差的机会，但旧端点的运行环境和种子仍是历史条件。第二种做法适合检验算法在相同资源下的差异。此次实际新增 GPU 使用为 0。

## 复核

使用项目验收环境中的 pandas、scikit-learn、certifi 和 MLE-bench 依赖。在仓库根目录执行以下命令。私有标签仅供评价脚本读取。32 份预测及大文件保留于外部缓存。

```sh
work=$(mktemp -d)
exp=experiments/paired-prediction-audit
python -B "$exp/collect.py" "$work"
python -B "$exp/inventory.py" "$work/trees" "$work/inventory"
python -B "$exp/score.py" "$work/inventory/pairs.json" "$work/labels" "$work/predictions" "$work/scores.json"
python -B "$exp/pilot.py" "$work/inventory" "$work/pilot.json"
```

作者数据固定在 [PredictBeforeExecute 的归档提交](https://huggingface.co/datasets/zjunlp/PredictBeforeExecute/tree/6b322cb88bdbcb2b2d3897ec7d0ded94a5bb2d06)。[标签定位与校验](label_members.json)记录作者 ZIP 中 4 个直接相关成员的文件名、偏移及 SHA-256。CPU 评分不会运行参选程序；32 个分数及文件指纹可逐行复核。
