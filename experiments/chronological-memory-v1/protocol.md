# Can earlier validation runs help rank the next batch?

Registered on 2026-11-10 before computing this audit. The corpus pilot and its four feedback archives have already been inspected. This is a feasibility and signal check on archived ForeAgent trajectories, not an estimate of online policy gain.

1. Use the 15 pinned author journals and their logs, plus our standard Stanford run. Reconcile the 129 complete author batches and seven local batches against the frozen reproduction. Each batch contains ten siblings. Reject incomplete or missing-journal batches.
2. At the first generation event, freeze up to ten most recent valid distinct executed node IDs in that run. Each must have an earlier log parsing event and an earlier journal step than every sibling, code, a finite metric, successful execution and the benchmark direction. Use validation metrics reported to the historical agent. The prediction function gets only these history codes/scores and current codes. Multiple submissions with similar code are possible. Current or later nodes and private scores never enter retrieval.
3. Carry forward the corpus pilot's word unigram/bigram TF–IDF, sublinear counts, cosine-weighted three nearest neighbours and midranks of past utility. Fit vocabulary on accessible history and the current batch. Require three history nodes for this check. Fix the ten most recent as a deployable replacement for randomly drawing ten from the full corpus. The reference is the original ForeAgent's logged decisions, not a newly generated C0 run.
4. Report availability of three and ten prior nodes and the fraction of sibling batches with two actually executed, valid, strictly ordered validation outcomes in the task's direction. Compare predicted and observed order **only within those batches**, scoring prediction ties as 0.5. Compare to 100 deterministic within-history score shuffles and the logged display order on exactly the same pairs. Average pairs within batch, then batches within run, runs within task, tasks equally. Report denominators by task. The historic execution policy determines which outcomes are observable.
5. Positive concordance above both controls across multiple tasks motivates an equal-budget prospective pilot with independently scored siblings. Sparse or mixed evidence calls for paired candidate executions to identify selection quality. An offline null on a small selected subset is inconclusive. CPU only, no paid calls, no training, one registered design. Freeze method choices for this readout.
