# DeepSeek 比较两份代码时，加上 comparison skill 会更准吗？

在 12 个开发任务的 24 对作者代码上，原提示判对 **32/48 次（66.7%）**，加入两条比较指令后判对 **31/48 次（64.6%）**。两种提示均使用同一个 DeepSeek-V3.2 Thinking 对每一对做 A/B 和 B/A 两次独立判断，按代码身份核对作者实测胜者。样本中相差 **−2.1 个百分点**，按 12 个任务配对重采样的 95% 区间为 **−16.7 至 +12.5 个百分点**，双侧任务符号翻转检验 p = 1.00。继续使用原提示，这一版不进入默认裁判。

| 同一批 24 对 | 原提示 | 原提示加 skill |
|---|---:|---:|
| A/B 顺序判对 | 17/24 | 15/24 |
| B/A 顺序判对 | 15/24 | 16/24 |
| 两种顺序选择同一份代码 | 20/24 | 17/24 |
| 两种顺序都选中真实胜者 | 14/24 | 12/24 |

按每对在两个顺序里答对几次来比较，**3 对变好、4 对变差、17 对持平**。每种条件只采样一次，因此换位一致率包含模型本身的采样波动。方法测的是两份代码的胜负预测；整轮搜索和代码生成属于其他实验。

在鸟鸣分类的一对里，原提示两次都选 B，加 skill 后两次都选 A。两次附加指令下的回答都指出 A 从音频计算梅尔频谱和差分特征，B 在频谱图像上使用预训练 DenseNet，并偏向 A。代码确实用了这两种处理，但作者实测 AUC 是 A 0.72076、B 0.72618，B 更高。这是按冻结清单顺序第一对从全对翻转到全错的案例。

**改动。** 原提示沿用作者的任务说明、数据分析和代码判断指令，已经要求权衡方法复杂度与任务特点。新增两条要求模型引用实际训练或预测路径中的代码差异，再判断哪处差异最影响指标。原提示和 skill 组都重新调用模型；给定同一种代码顺序，移除这两条指令后，逐份请求完全一致。[原始协议](protocol.md) · [完整 skill](skill.txt)

**样本与防泄漏。** 样本在调用前以提交 3150dde 冻结。26 个任务中的全部 18,438 对，经质量和代码长度筛选剩 18,231 对。24 个任务各有至少两对互不共享语法树的候选，固定哈希从中选了 12 个任务、每任务两对。每对代码合计最多 48,000 UTF-8 字节，按完整原文发送。筛选条件和固定哈希见[抽样脚本](prepare.py)。[盲清单](blind_manifest.json)与[评分答案](ground_truth.json)分别保存，模型只看到任务、数据分析和两份代码。24 对均有作者已知的、有限且不同的成绩。

**实耗与复核。** 96 次请求均收到不同的响应 ID，返回模型均为 Pro/deepseek-ai/DeepSeek-V3.2，均完成并解析出一个胜者。温度 1，两臂采用相同预算，实际平均输出（含思考）分别为 2,192 和 2,555 tokens。全程 37 分 44 秒，按返回用量和平台价格估算人民币 4.62 元。作者候选代码沿用既有跑分。计分器逐个从作者文件重算胜者、从模型最终答复提取索引，再按显示顺序映射到代码身份。[计分汇总](summary.json) · [逐对结果](per_pair.json) · [运行收据](results/receipt.json) · [平台价目](https://siliconflow.cn/pricing)

从仓库根目录执行以下两条命令可以复核输入、重算结果，均不调用模型。实际调用入口和全部设置见 [runner.py](runner.py)，评分口径见 [score.py](score.py)。运行需要已恢复的固定版本作者 corpus。

```sh
python3 -B experiments/deepseek-comparison-skill-v1/runner.py
python3 -B experiments/deepseek-comparison-skill-v1/score.py
```
