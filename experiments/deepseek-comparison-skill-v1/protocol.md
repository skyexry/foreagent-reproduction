# DeepSeek comparison skill pilot

The advisor asked whether a reusable comparison skill makes DeepSeek more accurate when judging two ML programs before execution. We predict that tracing a concrete difference to the implemented training or inference path will improve discrimination. The established comparison already asks about the task, data, complexity and trade-offs. This study tests only the extra directions in [skill.txt](skill.txt).

**Pairs.** Use the author's scored two-code comparisons from PredictBeforeExecute revision 6b322cb88bdbcb2b2d3897ec7d0ded94a5bb2d06. Before making requests, freeze a hash-selected sample of 12 eligible tasks with two pairs each. Require finite unequal scores, different syntax trees, four distinct syntax trees per task, and at most 48,000 UTF-8 bytes of code per pair. Select by deterministic hash, without using margin or any judge's past answer. Assign canonical A and B from score-independent content identifiers. The blind manifest contains code locations and hashes. Ground truth is held separately for scoring. This is a development pilot, with two pairs per sampled task; the number of API calls is not the number of independent tasks.

**Treatment.** Call the same SiliconFlow Pro/deepseek-ai/DeepSeek-V3.2 with thinking enabled in both arms. Use the historical corpus prompt builder with the author's task description and data analysis, full original code, CoT and prompt boost, temperature 1, thinking budget 32768 and max tokens 8192 as in the project's earlier run. Original receives this prompt unchanged. Skill receives the two lines in skill.txt immediately before the response-format instruction. Each request is a fresh conversation. Each pair yields four judgments, original AB and BA and skill AB and BA. A swap reverses the whole solutions, including each solution's filename, while keeping the indices tied to the display positions. Request order is seeded and mixed across the four conditions. Seal the sample, skill and request configuration before collecting outcomes.

**Scoring.** Map displayed winner index back to the same underlying code for each orientation. A correct choice matches the corpus winner regardless of confidence. Primary accuracy is the mean of the two orientation scores per pair, averaged within task and equally across tasks. Report raw counts out of 48 judgments per arm, percent-point difference, each orientation, pairs improved/worsened/tied, pairs selecting the same code in both orientations and pairs correct twice. Make-prediction coverage uses parsable in-range answers; completed but unusable responses receive zero primary credit. Report the subset with all four valid responses separately. A provider outage with unsent work leads to a partial-coverage report; an entirely unrun test has no accuracy estimate. Report the paired 95% task-bootstrap interval and two-sided exact sign-flip test of the task-level differences under sign symmetry. Describe an observed improvement as a pilot result; if uncertainty includes zero, reserve claims of a reliable gain. The study measures pairwise accuracy and does not measure downstream tournament regret.

**Budget and stopping.** One draw per cell, 96 first attempts. No new training, candidate execution or GPU rental. Allow at most one retry for a definite pre-inference rejection or transient transport/service failure, tracked separately from usable model responses. Preserve length-limit completions and parsing failures as observed. Stop for an unavailable model, invalid credentials or insufficient credit; never switch models between conditions. Finish and score the frozen sample before making prompt changes.
