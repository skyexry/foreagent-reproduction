# Run-held-out history control v1 — fixed before evaluation

Question: does the same-task, judge-selected execution memory from embedding-rerank-v1/history-control still improve selection when its only reference scores come from *other generating runs* of the same task? The previous 0.2250 DeepSeek loss allowed related off-pool siblings. Predict a smaller but positive gain after isolation. This one CPU contrast addresses within-task transfer only; these 26 development tasks and this corpus were used before.

Keep all 425 frozen candidate pools, both C0 schedules, all four archived judgment banks, the five fixed history permutations, identical CodeT5-small cosines, three-neighbor within-history utility percentiles, equal rank fusion, and uniform end ties. The target pool often spans several runs: exclude the UNION of every target candidate's generating runs for every query in the pool. Decode the run UUID before the final "_run_" in the author's filename, not the node identifier after it. If any target lacks a UUID, consider the pool ineligible; never use unknown UUIDs as strict references. Exclude syntax-tree copies of ANY code from a blocked run and exact target syntax trees, deduplicate each library by syntax tree. Distinct runs may still use similar templates.

Arms in one paired experiment:
- C0: no reference outcomes.
- Matched mixed-run memory: permit same-task, off-pool references from target runs (as in the previous study).
- Strict other-run memory: same algorithm, references only from allowed runs of the same task.

Use n = min(10, floor(strict library size / 2), floor(mixed library size / 2)). If n < 3 or provenance is missing, use C0 for both memory arms. Otherwise offer n disjoint reference pairs and reveal one outcome per pair according to the archived judge at confidence >= .7 or the same seeded fair coin. Couple the arms: sample 2n mixed codes with the previous seeded procedure, keep eligible draws in place, uniformly replace all excluded draws without replacement from the other unused strict codes (separate fixed RNG); use identical pair positions and fallback coins. This gives each arm a uniform ordered sample from its eligible library. No target outcomes for retrieval, history choice, ties, or ranks; evaluate only after decisions. Previous unrestricted metrics remain a published scale reference; the matched mixed arm is the comparator for the effect of source at fixed history size.

Primary report: macro-by-task normalized selection regret on all 26 tasks, with explicit C0 fallback; also macro on eligible pools within each eligible task, number of eligible tasks/pools/schedules, and n distribution. Report matched mixed minus strict and C0 minus strict with paired 95% task bootstrap intervals (10,000 fixed resamples, as before), separately for DeepSeek and pooled GPT. Context: overlap between selected reference codes and target runs, average nearest-reference cosine on eligible pools as a descriptive similarity measure, not proof of independent sources. GPT runs, pools and permutation seeds do not supply independent tasks.

Advance only if strict improves over C0 by >= .01 on all-task macro AND interval lower bound > 0 for both judge families. Otherwise report whether coverage or uncertainty constrains the inference. Different source and lower available coverage need separate interpretation. One frozen comparison; no tuning, additional model calls, GPU executions, research on new tasks or HW3 edits. Save per-task results and the reference IDs and final top sets so sampling, isolation, label count, and losses can be audited.
