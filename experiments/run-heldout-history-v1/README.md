# 同一个任务，执行记忆能从别次运行迁移过来吗？

**这版方法在同任务、不同原始运行之间没有显示出稳定收益。** 在相同数量的可见成绩下，排除和目标同源的代码，DeepSeek 与 GPT 两组的平均选择损失都回到原 C0 附近。[评分前固定的协议](protocol.md) · [数值和区间](run-001/summary.json)

举例：一个目标池里有运行 A 和 B 产生的十份代码。两种记忆都看同一任务的其他代码及其 corpus 执行成绩。混合组可以参考 A/B 的其他草稿；严格组只准参考 C/D 等别次运行。每次各看同样多的成绩（3–10 个），再判断目标池里选谁。两组固定同一个 C0、代码向量、历史配对预算、置信度和融合权重。严格组连 A/B 的池外程序的完全相同语法树也一起排除。其余近似模板仍可能共享。这里的“历史”由 corpus 构造，成绩是模拟已知参考分，不代表真实 Agent 在时间顺序上已看到这些分数。

| 全部 26 个开发任务，任务等权；越低越好 | DeepSeek 判断 | 三份 GPT 判断合并 |
|---|---:|---:|
| C0 原选择 | 0.2642 | 0.2725 |
| 混合组：参考数与严格组相同 | 0.2554 | 0.2551 |
| 严格组：仅参考其他运行 | 0.2654 | 0.2724 |

严格组比 C0 的改善分别是 −0.0012（95% 任务重采样区间 −0.0216 至 +0.0235）和 +0.00005（−0.0137 至 +0.0138）。隔离来源本身的代价，即固定数量后严格组减混合组的损失，为 +0.0100（+0.0012 至 +0.0198）和 +0.0173（+0.0019 至 +0.0360）。事前推进标准是两组都至少改善 0.01 且区间下界为正，这版没有达到。区间以这批已用于开发的任务为条件。

**覆盖。** 877 个候选中，874 个从作者文件名取得运行 UUID，覆盖 205 个任务内运行；3 个来源未标明的代码均在同一个小任务，涉及的目标池保守回退 C0。425 池中 287 池（16 个任务、每个判断归档 574/850 场）有至少 3 个可用参考成绩；另外 138 池两组共同使用 C0。在有足够历史的池内单独按任务等权汇总：

| 仅可比较池（16 个任务） | DeepSeek | GPT 合并 |
|---|---:|---:|
| C0 | 0.2827 | 0.2889 |
| 混合组 | 0.2674 | 0.2577 |
| 严格组 | 0.2839 | 0.2875 |

在这些池，混合组所选参考中，与至少一个目标候选属于同一次原始运行的比例为 64.0% / 65.9%（按任务等权）；严格组为 0%。每个目标到最近参考的平均 CodeT5 余弦相似度，混合组约 0.989，严格组约 0.986。表面相似仍然很高。结果支持“这版方法对历史来源敏感”，无法辨认是共享代码改动、同一生成模型习惯，还是其他运行特征在起作用；同一次真实搜索中的迭代草稿仍有实际使用价值的可能。

**上一轮 0.2250 怎么理解？** [上一轮同任务实验](../embedding-rerank-v1/history-control/protocol.md)在有较多可见成绩、且允许同源草稿时，DeepSeek 由 0.2642 降到 0.2250。切到本轮相同的覆盖与较小历史预算、仍允许同源时为 0.2554。再隔离来源为 0.2654。前两轮还存在抽到哪些参考、哪些池回退等差异；固定预算判断来源的直接对照是本轮的 **0.2554 对 0.2654**。这是在已见任务里的跨运行试验，新任务泛化留待另测。

本轮不再调整这版检索器；建议下一个最小对照直接检验老师的 comparison skill，在同一批已评分代码对上比较原提示与“引用真实代码差异再判断”提示。对新生成的代码迭代、训练 process reward model 和在线 GPU 运行分别评估。

复跑：从[版本附件说明](../../provenance/first-alignment-20261110/README.md)按原路径恢复作者代码、冻结向量；依赖 Python、NumPy、SciPy。工作目录为仓库根。输出包含[逐池覆盖](run-001/coverage.json)、[逐任务损失](run-001/per-task.json)与[逐次参考代码和选择](run-001/decisions.jsonl.gz)。决策每行为判断归档、场次、抽样序号、混合/严格参考 IDs、C0/混合/严格入选 IDs，平局按均匀选择计分。

```sh
work=$(mktemp -d)

```
