## 重放与复核

每个 gate 保留归档裁判的合法性、置信度、0.7 门槛和相同查询上限。C0 按真实赛制逐步发起查询，四个学习臂仅在该边被采纳时替换其胜者。每场最多读取 13 条唯一反馈。不同臂可以进入不同复赛，实际读数随轨迹变化。测试池候选、初始顺序、随机种子和执行效用按注册协议冻结。

在项目根目录运行。首条命令需要训练输出中的完整预测封存；每次重放采用新目录。

```sh
python3 -B experiments/trajectory-weighted-judge-v1/evaluation/replay.py --output experiments/trajectory-weighted-judge-v1/evaluation/run_1
python3 -B experiments/trajectory-weighted-judge-v1/evaluation/audit_folds.py --output experiments/trajectory-weighted-judge-v1/evaluation/run_1
python3 -B experiments/trajectory-weighted-judge-v1/evaluation/score.py --output experiments/trajectory-weighted-judge-v1/evaluation/run_1
```

| 输出 | 含义 |
|---|---|
| `selection_seal.json`、`decisions.sealed.jsonl.gz` | 先验证预测封存与环境收据，再运行 4 份 gate × 5 臂 × 850 场。每场保留选集、实际读取边、胜者、置信度与预算台账。评价标签由后续独立进程读取。 |
| `fold_audit.json` | 从冻结代码、任务局部 credit、编码向量和每折模型独立重建训练样本、训练集标准化与留出预测。 |
| `summary.json` | 任务等权损失、并列均匀时最佳命中概率、查询数、边与候选覆盖；terminal 对三个训练控制与原 C0 的配对差，各臂和原 C0 的配对差，以及四项主门槛。 |
| `per_task.json`、`per_pool_size.json`、`per_episode.jsonl.gz` | 逐任务、候选池大小和逐场结果；先在任务内平均，再在任务间等权。 |
| `pair_accuracy.json` | 全部不同代码两两组合、原反馈存在的边与原 gate 接纳边。每对只计一次，准确率在执行分数有严格胜负且有预测的边上计算，并报告覆盖与真实平分数。全组合中的原裁判准确率使用其有合法方向的部分；原 gate 接纳边提供双方面对相同题目的准确率。 |

每个任务的损失度量为所选候选相对于本池最优、最差效用跨度的归一化差距，并列选集中均匀抽取。配对区间使用 10,000 次任务簇自助抽样；逐一留出敏感性以固定预测移除一份任务结果。GPT 三份归档共享开发任务，每项单列，并另给先在任务内平均三份归档的结果。

replay.py 逐边核对原始端点顺序、采纳状态和预算，拒绝每种缺预测或端点非法的情况。原始 C0 的四份归档与以前的 3,400 份封存轨迹逐项相同方可评分，DS1 在评分时再次与原版 850 场收据对齐。实验所用为冻结 CodeT5-small 编码器与 1,024 维线性打分头。「普通执行监督」描述的是训练目标；ForeCritic 论文的 9B 模型和端到端成绩属于另一实验设置。
