# ForeAgent 基线复核 · 模拟 ICML 审稿意见

**判定：离线复现结果可以采用。若主张 R7 普遍优于简单胜率，或调低门槛能降低完整 Agent 的训练成本，证据需要大修。** 最有信息量的对照是同一场给三种方法完全相同的判断，并把最后的选择统一折算为选一个候选。本次没有调用模型或训练候选。

## 主要发现

| 重要性及证据 | 修正或结论 |
|---|---|
| 主要：之前的六点搜索只调原版淘汰赛。R6/R7 及 R8 回放重复使用固定 0.70；按旧接口传入 0.60 下已接受的 0.60 判断，汇总层会按 0.70 拒绝该输入。历史 R6–R8 原本都用 0.70，原结论在该门槛下仍可复现。 | 一个门槛显式传入控制器、去重/验票、R6 和 R7。注册后给每种方法同样的六个门槛、同一反馈模型、候选顺序、种子和各场反馈。选择函数接收 ID 与判断，真实分数只到评分函数。三者的可训练参数均为零，候选生成器与判断模型使用已存输出。 |
| 主要：旧六点实验保留作者缓存方向行为；缓存修复会改变路径和后续 RNG 消耗。 | 本轮用方向修正版作为公共控制。旧原版 0.50 与新 R7 0.70 的差异同时含控制器、门槛和汇总规则，不能归因给其中一个。冻结原版的 7,457 次有效方向错配与修正版的零次错配分别保留。 |
| 主要：模型自报 confidence 的数值尺度不同。事后诊断在同一组 18,389 对真实成绩有限且可区分的代码上核对。 | 0.70 的 DeepSeek 接受率 57.07%，接受项正确率 65.46%。三份 GPT-5.1 接受率 80.47%–80.95%，接受项正确率 60.89%–61.44%。这两组正确率条件于不同的获准子集。R8 能检验在同一反馈源内部换汇总规则的效果。比较反馈模型本身还需要在开发集确定等覆盖率或校准规则，再用于独立任务。 |
| 主要：命中、损失和执行成本对应不同决策。最高组可有多个候选，实际 Agent 对该组抽取且空选时强制执行第一位。 | 本轮以并列均匀选一个评分，每方法的选择数恰为一。逐场共享、按无序对去重的反馈数作为比较成本。训练时间、实际执行次数、真实 token 和 API 成本不能从这一估计推导。此处“相同预算”在同一门槛内逐场成立；跨门槛的判断数可变。 |
| 主要：26 个任务和三个 GPT 反馈都已看过。部分池反复使用完全相同的候选：四个小任务各自只有一个无序候选池。 | 统计单位取任务；同任务内所有重复共享一个权重。18/8 的固定划分只用于本次开发选参。区间是逐门槛、描述性的任务 bootstrap，未作六重比较校正。真实外部泛化仍须保留新任务。 |
| 中等：246 对的两边重试策略不同。双方使用相同样本，但本地首轮 123/246，20 个失败各重试一次后 136/246。作者保存的单次结果 130/246；该样本恒选第一位也有 131/246。 | 报告分母、位置基准和两轮结果；其中双方历史实际服务端调用数未完全匹配。6 对差距不足以证明比较器更好。缓存反向读取的测试也不能测量模型真正交换 A/B 后的位置偏差。 |
| 中等：置信度缺失时回退到 0.50；在网格下边界 0.50，该判断能投票。 | 所有方法使用相同回退和大于等于规则。0.50 与 0.70 的差值混合了降低门槛以及纳入缺失项两种作用；六档最优只在本次数据和网格内成立。 |

## 匹配参数和预算后的结果

26 任务 × 300 场 × 6 档 = 46,800 场、140,400 个方法评分。默认档的三方法命中和 regret 分任务核对历史记录。26 任务的 R7 减 R6 regret 在 0.70 为 −0.009749（95% 任务区间 −0.02663 至 +0.01120），在 0.50 为 +0.000014，在 1.00 为零。择优展示 0.70 会夸大结论的适用范围。

开发时三方法使用完全相同的目标、约束和六次机会；在 18 个任务上均选出 0.50。下表是另外八个已见任务上的等权均值。

| 选择规则（0.50） | 单选最佳命中率 | Normalized regret ↓ | 每场唯一判断数 |
|---|---:|---:|---:|
| 缓存方向修正版淘汰赛 | 28.625% | 0.323666 | 7.2825 |
| R6 简单胜率 | 30.375% | 0.334686 | 7.2825 |
| R7 胜率并列按有效比较次数 | 30.375% | 0.334686 | 7.2825 |

三者满足预先约定的验证约束。R6/R7 更常命中第一，但平均损失比淘汰赛高 0.011020。上述两个平均指标相同并不单独证明逐场选择相同。调参后若主目标仍是 regret，这八个任务支持优先保留淘汰赛对照。作者正式设置仍为 0.70。

## 实现问题与复核

- 原 R6 读取器能把 -1 当作最后一个候选，把 0.9 截断成第一个候选。已显式检查胜者，只接受数值 0 或 1，拒绝布尔值。已测三个反例。
- 补充评分器曾允许重复的 top ID。加强成员、唯一性和 rank-0 一致性检查。R8 也检查全部统计/排名的键以及每条 trace 的候选身份。旧冻结独立评分器的并列真值与全相等问题仍由补充评分器覆盖。冻结语料中没有真实成绩并列池。
- Python 优化模式会移除 assert；旧冻结脚本还会信任工作区自己的清单。审稿分支的推荐入口显式拒绝优化模式并把 85 个文件清单锚定到已发布提交的摘要。R6/R7 运行和核验锚定原注册清单；R8 锚定评分前的两个提交。审稿入口的空清单和优化模式反例都被拒绝。原发布标签保留其历史实现。
- 排行榜获取原先只遍历本机现有路径，漏文件可能被记成全部通过。现从固定 Git 树枚举 30 条路径并校验每一项；遇到冲突的本地内容报错。
- R6/R7 完整独立重算各 7,800 场。R8 扩大原先 78 场的原生控制抽查，按保存反馈重演全部 23,400 场，独立核对 70,200 个方法评分。原历史作者部分仍是给定判断与已记录概率动作的条件重演，129 个完整批次通过，另有 11 个不完整或缺 journal，原始复赛对手和 RNG 状态仍是证据缺口。

## 可复跑入口

安装与固定输入沿用根 README。历史资料从发布标签以及 R6–R8 原提交获取。以下命令均在本审稿分支根目录采用普通 Python；校准划分/完整结果在 experiments/environment-audit 和 experiments/icml-review。

```sh
python scripts/review_preflight.py
python -m unittest discover -s tests -v
# 新目录、已获取历史和 corpus 资料及 pairwise 附件
python scripts/review_preflight.py all
PYTHONHASHSEED=0 python scripts/review_fairness.py runs/fairness.json
python scripts/review_feedback_scales.py
# 已获取 R8 三份数据和对应输出的副本
PYTHONHASHSEED=0 python reproduction/round08/verify.py --all-native --output runs/round08
```

数据和附件有版本与校验值。R6–R8 的完整产物目前有本地独立附件，不能假设只克隆远端 baseline 标签就能获得后续研究分支和附件。机器为 macOS arm64，离线结果不提供 GPU 时长。要作出新任务或在线收益结论，需要分别完成前瞻新任务评价，以及相同硬件、生成器、时间和执行预算下的 AIDE/ForeAgent 运行。实际模型参数总量、服务端重试和算力无法由这些已保存回答反推。
