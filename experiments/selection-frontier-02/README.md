# ForeAgent 开发实验｜先改哪个模块？

**结论：下一版先改两两裁判的胜者预测，再评弃权处理。当前继续使用 C0。** 直接可运行的选边、终选和预算改动未稳定胜过原基线。最后一项实验指向裁判质量。普通执行监督属于 ForeCritic 式基线，训练机制另列为待验候选。[一页改动方案与验收标准](优先改动.md)

本轮以原版已修正的 C0 淘汰赛为参照，目标是在同等预算下选到执行成绩更好的代码。所有结果均来自已查看的开发任务。优先级判定分两层：可以直接运行的改动，用真实归档判断测收益；理想化干预只用于判断下一项模块值得解决什么问题。

## 上一轮 73 个反例解释到哪里

先固定旧链后随机的有效边，再假定每条有效边都给出正确胜者。在全部 850 场中，438 场的首选集合完全漏掉真实最优者。其中 177 场最优者所有已问边都弃权，另 261 场最优者已经有正确胜利，却因同胜率下对手数较少而落选。还有 223 场首选并列中包含最优者，189 场只选中最优者。按相同任务等权口径，0.09815 残余损失中，这三类损失分别贡献 0.03665、0.03098、0.03052。

只看此前的 73 场恶化案例，15 场属于最优没有有效边，28 场属于对手数破平压下最佳，30 场仍有部分并列。已实测的有效覆盖策略专门处理第一类；它将查询移向缺证据者，却没有相应增加最优者的正确胜场。这个结果说明，**发现一种失效现象，和改写规则后真的选得更好，需要分别验证。** [分组、分母与逐场例证](coverage/README.md)

## 最后用于定顺序的实验

先用不读取成绩的哈希将每个任务内的候选对分为四组。一次只干预其中一组，分别重走 C0 实际淘汰、缓存、复赛和停止过程，最后对四次取平均。D 使用真实执行胜者纠正原本会被 C0 接纳的错判，置信度和所有弃权维持原值；A 只给原本会弃权的严格胜负提供正确方向和 .7 置信度。原执行成绩并列时保留原判断。相同预算上限、相同事前地址机会；实际可纠正的错误数、被补足的弃权数及后续赛程可各不相同。这是在评价器侧模拟局部补充真实信息，两臂均需读取执行答案。

| 完整26任务的比较 | D 纠正已采纳判断的收益 [95%区间] | A 补足弃权的收益 [95%区间] | D 相对 A 的额外收益 [95%区间] |
|---|---:|---:|---:|
| 原 DeepSeek，温度1 | +0.06472 [.03617, .10215] | +0.06040 [.03901, .08336] | +0.00432 [−.01906, .03566] |
| 另一份 DeepSeek，温度0 | +0.04140 [.02327, .05852] | +0.03836 [.02350, .05602] | +0.00303 [−.01335, .01883] |
| GPT 三份记录，先在任务内平均 | +0.07543 [.05182, .10135] | +0.02409 [.01524, .03428] | +0.05133 [.03113, .07414] |

六个银行共 4,574 个“场次×银行”基准，配上四折、两项干预共 41,166 份选择。另一份仅覆盖10任务的 DeepSeek 记录，D/A 收益为 +0.06525/+0.07236，两者差的区间也跨零。全26任务三组的 C0/D/A 实际任务宏平均唯一读取分别为 11.21/11.18/10.77、11.16/11.20/10.78、9.98/9.98/9.60。对同一地址的机会干预不能当成每单位真实核验成本的对比。[锁定协议](judge-intervention/protocol.json) · [全量结果与共同10任务敏感性](judge-intervention/run_1/summary.json)

**为什么先做 D。** 它在三组完整任务上均有明确的损失改善空间，在 GPT 上对 A 有额外优势。DeepSeek 上两种干预的差值仍容许两个方向，因而这里确定的是工程顺序。D 可以用现有成对执行标签训练和评价，并固定原弃权掩码，单独检验胜者预测。A 要同时解决“何时接纳”和“接纳后判谁赢”，留作第二个模块。真实模型的收益以其预测重跑得到的结果为准。

## 证据如何解读

- 主实验使用 26 个开发任务、425 池、850 场，三次 GPT 按任务内先平均，再做任务等权配对。补充两份 DeepSeek 温度0归档，一份可覆盖26任务850场，另一份只能覆盖10任务324场；涉及两份共同范围的比较使用同样10任务，并保留单份全26任务统计。温度、运行时间和后端状态同时变化，归档比较不能单独归因于温度。[来源及核验](deepseek-transfer/README.md)
- 把主规则在不同任务、赛程、银行上分别检验。固定 C0 图的后处理与降低淘汰门槛后重走搜索是不同干预。判断来源的原始回答可见程度也不同；独立核查同时比较了保守排除恰好 .5 的判断和在相同低信心边上随机赋胜者。原 DeepSeek 的优势具有方向信息，GPT 的宏均值还受到少数小池任务影响。[C0 低信心机制核查](direction-audit/)
- 研究过程中新增的试验分别在运行前登记。初次正结果来自已查看的固定轨迹；后续三份 GPT 的真实 C0 路径、两份补充 DeepSeek 归档是逐步加严的验证。多个试验和区间用于在开发任务上决定研究顺序，不是多重检验校正后的论文确认结果。[首份协议与来源哈希](protocol.json)
- 新策略文件位于 [valid_coverage_v1.py](../../research/policies/valid_coverage_v1.py)。含新门槛、不同汇总或额外裁判的回放采用独立研究版本。受保护的 C0、既有原版输出与 host 评分器按旧版本保留。本轮新增付费 API、GPU、候选训练和在线 Agent 执行均为零。

**核验入口。** 两个子代理分别从原始记录重建排名、查询账本和 oracle 门控。最后的模块级比较逐项重核 475,411 次实际查询、41,166 份选择的评分及 90 组区间/留一统计。较早的真实规则改动也各自保留脚本、快照、失败记录和收据。[模块级干预复核](judge-intervention/run_1/verification_1/receipt.json) · [独立回放与成本复核](verification/README.md)
