# ForeAgent 比较与筛选流程核实

核实日期：2026-10-22。范围：论文 §6.2、已固定官方代码提交 `c4d52cf99bd870d830b456ac7c0684aec1aef375`、本地固定版语料与作者公开预测。没有调用 LLM API，也没有执行候选训练；没有修改原实验结果或上游代码。

## 结论

下一步应复现/适配的是 **confidence-gated tournament（置信度门控淘汰赛）**，不是普通胜率排序。它可以作为我们的离线 comparison/ranking 对照，但必须标明为固定候选池、固定比较反馈下的离线适配，不等同完整 ForeAgent Agent 复现。

## 实际筛选规则

1. 同一父节点生成一批改进候选。多候选时进入 `tournament_rank`；无候选则回退普通 improve，单候选则直接执行。
2. 每轮按当前列表相邻位置配对，奇数余下者轮空晋级。不是每轮全体互相比较，也不是先随机打乱列表。
3. 置信度 `>=0.7` 时胜者晋级、败者淘汰；低置信度或调用失败进入 pending。
4. pending 候选随机挑选一个已晋级候选再比较。如果没有已晋级者，先让一个 pending 直接晋级。复赛赢了则 pending 晋级，输了则淘汰；仍不确定则继续保留。pending 赢了不会移除已经晋级的对手。
5. 重复直到剩一个候选，或轮数大于 `2*n` 时安全退出。没有显式的固定 LLM 调用次数上限。缓存会使比较记录数和新调用数不同。
6. 最终按“未淘汰优先、胜场降序、轮次降序”排列。显示名次按连续的 `(wins, round)` 组递增，相同组并列；稳定排序可能保留输入顺序。
7. Agent 按 `wm_predicted_rank < improve_top_k` 判断 Top-K，因此 k=1 不保证只有一个候选。Top-K 内的每个候选先以 `exec_probability=0.2` 决定执行，Top-K 外跳过。若概率检查后执行数为 0，代码会强制执行第一个 rank=0 候选（找不到则取排序第一项）。因此唯一 rank=0 候选最终仍会执行，并列 rank=0 时可能执行多个。函数注释中说概率用于 Top-K 外，与实际调用路径不符，应以代码控制流为准。2026-11-07 已用原 Agent 方法和假执行回调补验，见 `foreagent_mechanism_audit.md`。

## 不联网模拟发现

使用 `verify_foreagent_selection.py` 对固定源码运行本地假响应；只替换依赖包导入、Node 和 query，不改比较/排序方法。断言全部通过，细节见 `foreagent_selection_checks.json`。

- **缓存顺序问题确认**：缓存 key 使用无序代码 hash 对，缓存内容却保存当前请求中的 0/1 索引。A/B 返回 A（索引 0）后，反向 B/A 命中同一缓存仍返回索引 0，解释成 B。模拟中只有一次假调用即可复现。缓存也不包含任务/提示配置；这是固定版本的实现局限，不能带入新实验后默默当成正确身份映射。
- **全高置信度**：10 候选淘汰赛使用 9 次新比较，产生单一最高名次。
- **全低置信度**：2 候选、置信度 0.6、门槛 0.7，达到第 5 轮安全退出；两者均 rank=0。共 10 条比较记录，但只有 1 次新假调用，其余命中缓存。因此不能把每条复赛记录都当作新证据/新 API 调用。
- **执行概率**：配置 0.2 时，模拟随机数 0.19 会执行，0.21 不执行。

缓存问题尚未修复。后续应保留原实现行为作审计参照，并将按候选身份映射的修正版明确命名，不能把修正偷偷混入“忠实复现”。

## 固定公开预测回放的适用性

对 26 个任务的 ground_truth 配对集合与已下载作者预测记录检查，结果见 `foreagent_replay_coverage_check.json`：

- 17 个任务的候选配对图不完整，不能保证任意选中的两候选都有反馈。例如 petfinder 有 30 个候选，仅 239/435 条可能配对。
- 4 个任务不足 10 个候选：dog-breed、nomad 各 3 个，jigsaw 5 个，plant-pathology 6 个。不能无声补齐为 10 个。
- 作者公开预测中 1,978/18,438 条缺少 confidence 字段。本次统计没有基于正确率筛选记录；缺失项不能从理由措辞编造。
- 相同候选在各配对中的保存分数未发现冲突。这里是记录一致性检查，不是重新执行验证分数。

Agent 的解析器将缺失或不可转换的 confidence 置为 0.5，因此在 0.7 门槛下会视为低置信度。但 corpus 的提示词原本允许可选 confidence，Agent prompt 明确要求 confidence；采用 0.5 回退虽符合解析器逻辑，却不证明实时 Agent 也会有同样的缺失率。应额外报告缺失影响。

回放还必须按候选身份正确映射方向；反转一个已有判断只是复用记录，不能作为新的交换顺序实验。只读取策略已查询的胜者/置信度，真实分数留在最终评分端。

## 对我们下一步的具体含义

建议先冻结协议，再实现以下对照，当前尚未开始新排序实验：

1. **ForeAgent 淘汰赛离线适配**：保留相邻配对、0.7 门槛、pending 复赛与排名规则；明确缓存修正、固定候选池替代同父节点生成候选、缺失反馈和并列选择政策。原实现不保证单一 Top-1，不能随意挑第一个而不披露。
2. **共同反馈下的汇总对照**：简单胜率与 BT 接受完全相同的比较记录，单独检验汇总方式。ForeAgent 的自适应配对不一定产生同一张图，因此不能将“不同选对 + 不同汇总”差异全部归因于 BT。
3. **固定预算下的策略对照**：各方法使用相同候选池、允许的查询集合和新反馈预算。固定记录重复读取不增加独立信息，同时记录查询尝试数与唯一反馈数。若强行加入预算截断与最终选择规则，这是新增适配，不是原算法已有规则。
4. **选择与执行分开**：离线选优实验衡量候选选择质量，不实际运行随机概率执行。若取消 0.2 执行门槛，要明示这是“只评估筛选模块”；不能将所得结果当作完整 Agent 的运行节省或 Beat Ratio。

候选池、缺边处理、并列选择、置信度缺失、预算截断以及开发/测试边界，都是在看新排序结果前必须固定的协议项。原来的 246 对继续作为已查看的探索材料，不修改其结果。
