# ForeAgent tournament 本地回放协议

记录日期：2026-11-07。在首次查看本轮选择结果前写定。本轮为探索性基线诊断。

## 范围与版本

- 固定上游提交：`c4d52cf99bd870d830b456ac7c0684aec1aef375`。
- 从本地 Git 对象读取并校验 `world_model.py`，仅移除相对依赖导入。
- `original` 保留原始比较与缓存方向行为；`cache_fixed` 在首次查询保持输入顺序，在缓存命中时按当前候选身份转换胜者/败者索引，并将缓存限定于实例。
- 每个任务/候选池/排列/复赛种子/版本使用新实例、空缓存。原版的跨任务缓存问题不在本轮测量范围。
- 原始 `tournament_rank`、置信度门槛 0.7、pending 复赛、轮空、轮数安全退出和排名规则保持原样。
- 替换 query 和 prompt 构造为本地反馈查表；node.code 使用唯一候选文件名作为身份标记。顺序执行原批次的比较，保持原批次输出顺序。它不测 API 并行调度或模型输出随机性。
- 本轮只评估筛选模块。0.2 概率执行和候选训练属于后续端到端验证。

## 数据与抽样

- 使用现有固定数据 revision 和作者一次公开预测，其版本与 SHA-256 来自 `coverage_manifest.json`、`coverage_author_reference.json`。
- 选择所有配对图完整且至少有 10 候选的任务：aptos、leaf、essay scoring、random-acts-of-pizza、tweet-sentiment-extraction。共五个任务。
- 每条作者预测以有序文件名短后缀和分数唯一匹配来源 pair；校验标签与分数方向。建立反馈表后只向选择器提供候选身份、预测胜者与 confidence；真实分数仅供抽样后的评分器使用。
- 种子 `20261107`；每任务对排序后的候选身份抽 10 个池，每池 10 个候选，池间允许重叠，同一任务的池集合唯一。
- 每池测试 5 种唯一排列：候选身份排序，以及 4 个固定种子随机排列；每排列测试两个 pending 随机种子（索引 0、1）。固定种子的完整字符串写入结果。
- 反馈保留作者记录中的胜者身份；交换顺序仅做身份映射，属于同一条证据。缺失/不可转换 confidence 按原解析器规则回退 0.5；异常胜者、非有限/越界 confidence、缺边、重复配对或分数冲突报错。
- 不按预测正确与否或分数高低筛选候选池；五任务筛选依据仅为比较图完整性和候选数量。

## 评分与轨迹

- 单选结果为原排序输出第一项；rank=0 的所有候选另外保存，以报告并列率、并列大小、随机选并列候选时的最佳命中概率。
- 最佳命中：所选分数等于池内最优分数。
- 归一化排名损失：池内分数严格好于所选候选的个数 / (池大小 - 1)。越低越好，避免混合任务指标单位。
- 随机选择参照使用精确期望：池内最佳候选占比、所有候选排名损失均值。
- 同时记录比较尝试次数、唯一反馈数、缓存命中数、反向缓存命中数、有效判断中的缓存身份错误、缺失 confidence 的唯一反馈数、安全退出率和最终排名。
- 保存每次比较的候选身份、轮次、反馈来源、是否缓存、期望/实际胜者和置信度到本地 `outputs/tournament-replay-20261107/`。
- 同一候选池、排列与复赛种子对照原版和修正版。汇总先按任务平均，再对五任务等权平均。
- 重叠候选池、排列及种子不是独立测试样本。本轮只报告描述性结果；结果不代表完整 Agent、全量 benchmark 或独立新任务泛化。

## 验收

1. A/B、B/A 缓存复用保留同一胜者身份，低置信度仍为无确定胜者。
2. 原版保留已确认的方向错误作为对照；修正版保留初次请求提示顺序、置信度门槛和轮次。
3. 不同实例隔离，反向并发请求只获取一次反馈。
4. 全高置信度的 10 候选 tournament 使用 9 条反馈；全低置信度覆盖安全退出和并列。
5. 现有预算/流式测试继续通过。
6. 固定种子重复运行得到完全相同的结果与逐次比较轨迹，修正版缓存身份错误计数为 0。
