# 候选生成与真实执行的历史方案

**这两套设计留作后续研究。当前优先从固定 corpus 评价离线候选选择。** [当前研究入口](离线候选选择.md)

**首选改候选生成和验证的配合。** 让 Agent 为一个真实的性能问题提出两个会给出不同预测的解释，生成能区分解释的改动，再用一次有针对性的执行决定下一版写什么。第二选择是改搜索树的父节点选择，给平均分一般、但在一类样本上有独特能力的候选一次继续改进的机会。这两套方案分别问“怎样获得可以指导改代码的证据”和“哪些代码值得留下来发展”。

## 方案一 · 一次比较，既选代码，也指导下一版怎么写

**为什么优先。** ForeAgent 已经会读数据报告、让同父候选参考之前的计划、预测胜者、执行并改进。我们的 Stanford 三架构短测还发现，各代码自报的验证分数受逐批计算 RMSE 和补零位置处理影响，统一重算可以追溯其中的差异。这是一个已有的可执行实例。更普遍的研究假设是，即便代码都实现正确，对整体分数给出的两个解释也可能指向完全不同的下一步。[作者生成入口](../phase1-reproduction/code/author/mle-bench/agents/aide/aide/agent.py#L368-L428) · [本地短测](../experiments/clean-ranking-v1/先读结果.md)

| 接下来几轮 | 对现有模块的具体改动 | 实验要回答的问题 |
|---|---|---|
| 第一轮 · 生成器和验证器 | 从父方案真实的任务内验证表现出发，先写下两个可区分的解释及各自预期的现象。给生成器两个候选名额，每个子方案只动与其解释有关的一处，保留父方案。验证器在看结果前选一种观察方式，同时写下什么结果会改变选择。 | 与等名额自由生成相比，成对的改动能否产生更有用的候选？固定同一批代码后，针对解释选的验证动作相对等预算的通用短跑，能否把更好的代码送去完整训练？ |
| 第二轮 · 反馈和改写 | 在相同的父方案、子方案和已执行记录上，允许一次改写 C。给生成器三种反馈之一：整体分数；由同一模型写的文字建议；带输入范围、失败实例或分组误差的真实执行差异。 | 额外收益来自取得了新证据，还是来自多给一次改写？三臂各得到一次机会和相同 token 上限。以另一组密封样本的任务指标比较 C 与起始方案，计入生成和验证失败。 |
| 第三轮 · 搜索控制和完整 Agent | 把经验证有效的动作接回搜索。控制器可以提交当前方案、花一次预算解决仍影响决策的分歧，或沿已有证据改写。先比较固定动作顺序，再评价动态分配。 | 在方法冻结后的新任务上，配对比较 C0、简单固定顺序和动态控制器。相同总墙钟与费用上限，报最终提交、有效提交率和达到同一成绩的耗时，逐项撤去新增动作。 |

**举例，属于设计假设。** 在罕见类别召回率低的分类任务上，可能是模型学不到少数类，也可能只是决策阈值过高。以同一父方案生成 A（只改训练类别权重）和 B（只改决策阈值），维持模型结构、数据划分和评价实现。验证器在独立于调阈值的数据上比较两者在相同精确率下的召回。若排序能力相近而调阈值即可恢复目标表现，下一份代码优先改决策层；若重加权提高了相同精确率下的召回，再沿训练目标改进。最终用任务约定的主指标复验。两种干预也可能同时有效，选出的短试只能提供下一步证据。

**第一个可执行实验。** 在指标和样本划分可统一、能在本地重跑的三个开发任务上，先冻结任务与两个父节点/任务，任务按可运行性选取并记录排除理由。每个父节点保留同一原版，生成两个子候选。交叉比较“自由生成 / 按两个解释生成”与“固定通用短跑 / 按分歧选择测试”。同一生成条件下，两种验证器看到逐字相同的候选。静态 C0 作为零新增验证的参照；在固定候选上另把同一菜单随机分配，识别有针对性地选测试到底贡献多少。菜单从统一评分重算、预先定义的样本分组、固定步数配对短训中选一项。第一版用规则限定动作与成本，推理模型写出选择和预期结果。完整执行成绩和密封样本只在外部评分器可见。

- **预算。** 每个起点/生成条件最多两份新代码；每个验证条件同一总上限、一次验证机会；后续改写实验每臂最多再生成一次。复用同输入的结果以节约研究开销，同时给每个实验臂按独立运行记账。登记任务可承受的秒数和 token 上限后启动，费用按实记。测试时所花的额外计算可从同一总时间里的后续训练扣除。评分专用全量执行各臂共用、独立记账。方法本身首版无需训练裁判或租用 GPU；候选的实际训练设备由任务决定。
- **成功与转向。** 主指标是相同资源下所选提交的独立得分，辅助拆成“生成池里最好的分数”和“所选与池内最好的差距”。同时统计选对改错、选错改对和探针失败。小先导以任务分列，衡量效应方向和资源可行性。只有证据可跨父节点复现、且相对通用短跑和随机测试有增量，才扩大评测。若只有定向生成有效，保留生成器；若只有定向验证有效，让它配自由生成；若改写只在用于产生建议的样本改善，结束该反馈分支。为防止单因素约束压低探索上限，保留自由生成作为真实竞争者。
- **实验入口与隔离。** 复用 [原 Agent 的生成/执行入口](../phase1-reproduction/README.md)、[C0 短测和统一评分](../experiments/clean-ranking-v1/先读结果.md)。新分支要增加“受限验证动作 → 实际观察、耗时、失败原因”的接口。现有 v1 仅返回已存判断，仍用于静态基线。完整新方案只在新实验 ID 与真实工作目录中运行。仿照 AI Scientist-v2 的节点记录，保留父代码、变更、事前预测、执行条件、观察、下一步和独立得分。[AI Scientist-v2](https://github.com/SakanaAI/AI-Scientist-v2)

**和已有方法的关系。** MLE-STAR §3.2、附录 A.4–A.6 已经做模块消融，按结果定向改代码，是此方案最重要的同预算方法对照。ExPairT-LLM 用可区分的输入测试候选程序；EffiPair 用已运行的结构相似程序间的效率差异指导改写；ForeCritic §4–5 学习静态成对偏好并接入搜索。这里要单独验证的增量，是在随机 ML 训练前共同设计候选改动和可观察预测，用有限的试验区分解释，并在独立样本上测量这一信息对下一次改写的价值。对照还应把“先做常规模块消融、再改分数影响最大的模块”与新方法置于同一生成器和执行预算下。研究范围覆盖这些直接近邻，更广泛的新颖性和实际增益仍待验证。[MLE-STAR](https://arxiv.org/html/2506.15692v1) · [ExPairT-LLM](https://arxiv.org/abs/2511.10855) · [EffiPair](https://arxiv.org/abs/2604.05137) · [ForeCritic](https://arxiv.org/html/2610.38439v1)

## 方案二 · 让表现互补的父方案各有一次繁殖机会

**改搜索树，而非只改最终排名。** 一份代码可能整体排第二，却在第一名最容易错的某类样本上更强。把每个已执行节点在相同验证样本上的误差留下，在原有扩展名额中用一个跟进当前最好方案、另一个跟进在其薄弱分组有独特优势的方案。分组在看到结果前按任务含义固定，分组内的优势需要另一份验证数据支持。选择父节点可借鉴 ε-lexicase 容许连续误差波动、保留局部强者的机制。此处关注后代质量，第一版按单份模型提交；MLE-STAR 与经典 ensemble selection 已覆盖结果互补时的集成。[ε-lexicase](https://arxiv.org/abs/1905.13266) · [MLE-STAR §3.3](https://arxiv.org/html/2506.15692v1) · [Caruana 等](https://doi.org/10.1145/1015330.1015432)

**最小实验与取舍。** 使用相同已执行父候选和对齐的验证预测，在每组相同的两个扩展名额中比较“扩展整体前两名”“第一名加随机父节点”“第一名加互补父节点”。每个获选父节点各得相同的一次生成和一次短训；密封样本上分别看最优后代和最终提交。若互补分组在独立样本上消失，或在相同生成费用下后代整体表现持平，结束该分支。需要真实的逐样本验证预测和父子关系，历史裁判胜负无法重建这种信息。它排第二，因为当前候选选择误差和可操作的验证口径差异已有实证，而被总体排名压下的分支是否更容易生成好后代仍是待验假设。

## 已完成的旧设计如何使用

- 置信度可以粗分判断难度。作者一份完整归档中，显式高信心组均值 73.62%、实际正确率 65.38%，低信心组正确率 54.53%。C0 主赛高信心败方淘汰，低信心进入复赛；终选看存活、胜场和轮次。这个机制适合做低成本初筛对照，决定验证价值时还需考虑错选的损失和取得新证据的成本。[置信度回读](../reports/reproducibility-audit-20261108/evidence/confidence.json) · [实际淘汰与复赛规则](../reproduction/clean_ranking_v1/overlay/world_model.py#L482)
- 静态裁判训练已收口。用 C0 终局损失给监督加权，在 26 个开发任务上相对等权训练的收益为 0.00116，95% 任务配对区间为 [−0.00232, 0.00448]，低于预登记的 0.01。结论针对本次冻结编码器和线性头；真实 C0 继续作为对照。[实验概览](../experiments/trajectory-weighted-judge-v1/README.md)
