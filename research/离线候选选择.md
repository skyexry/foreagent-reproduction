# 用同一份 benchmark 评价候选选择

**目标是给定一批已有代码、已花掉的两两比较预算，选出执行成绩尽量好的一份。** 生成方式和真实执行留作另一项研究。默认选择器是 C0。本页把新增代价、适用范围和两个有停止条件的离线试验放在一起。

## 先把三个对象分清

| 对象 | 本轮口径 |
|---|---|
| 任务 benchmark | 同一批 26 个开发任务、同一执行评分定义。每任务有一票；重复赛程或裁判记录均保留任务内相关性。 |
| 候选 corpus | 固定候选代码、已知执行成绩与配对关系。425 个池、850 个场景，较小的池也纳入。候选效用仅供全部选择封存后的评分。 |
| 被比较的方法 | 只换最后选哪份候选。每种方法在同一个场景看到 C0 实际问过的同一批对局，相同顺序、相同结果和费用。汇总器替换走新的离线实验 ID，保留 v1 host、输入与评分器。 |

**为何推迟生成、验证、改写方案。** 针对任务设计验证动作，每类任务都需要适用的实现、独立样本和预算，廉价试验与完整训练还可能给出不同顺序。改写 C 会引入一份旧 corpus 从未执行的代码。若将来研究生成，可以保留原 corpus，在相同任务、数据划分、评价器、时间与费用下分别运行生成策略，对各自新候选独立评分。若只研究排序器，双方须看到相同候选，混在一张旧榜里会把“生成更强”误记成“选得更准”。当前没有配对的在线成本与收益依据，生成方案的回本点仍未知。[冻结口径](modules.md) · [生成路线的原始设计](研究路线.md)

## 理由在哪里，能说明什么

作者比较提示要求先简述原因，末尾用 JSON 给出胜者和置信度。解析器用末尾 JSON 判断胜负，比较对象可保存 raw_response。Agent 写回节点的比较记录保留胜者、信心、轮次、有效性。固定 v1 排序输入提供已查询对的 a、b、winner、confidence、valid。DeepSeek 的归档 prediction.reasoning 在 18,438 条原始记录中有 18,435 条非空，在准入 17,877 对中有 17,874 对非空。非空文本的长度中位数约 9,858 个字符（准入口径）。归档的理由有时记下较早的判断；用文字预测胜负和检查它是否可靠是两个不同的问题。[作者提示与解析](../phase1-reproduction/code/author/mle-bench/agents/aide/aide/world_model.py#L166) · [节点字段](../phase1-reproduction/code/author/mle-bench/agents/aide/aide/agent.py#L687) · [字段计数与来源核验](../experiments/posterior-ranking-v1/verification/receipt.json) · [原答与保留文本的区别](../experiments/selection-frontier-02/direction-audit/README.md)

## 两个动作，共用候选和已有比较

**一、把所有已采纳胜负放在一起，重新选第一名。** 把每种可能的真实顺序都保留，每符合一条比较就把该顺序的权重乘 2；所有候选从相同权重开始，重复查询只算一次。主方法取加权平均名次最好者。固定 2:1 是计算假设，已采纳边的可靠性实际上会随任务和对局改变。原始工作给出含噪比较的排序模型，这里把单一最可能顺序改为对全部顺序求平均，并在 C0 稀疏赛程上评测。该方法只使用次序证据；真实效用差距还取决于代码间的分差。[Noisy Sorting Without Resampling](https://arxiv.org/abs/0707.1051) · [协议与代码](../experiments/posterior-ranking-v1/README.md)

四份归档各 850 场。相对 C0，任务等权归一化损失的改善，DeepSeek 为 −0.02138，95% 区间 [−0.09328, +0.02838]，三份 GPT 先在任务内平均后为 −0.00924 [−0.03098, +0.00486]。原始比较次数相同，新增排序计算平均约 3.48 毫秒 CPU/场。该固定方法成本很低，收益未过预设尺度，默认保留 C0。独立计算从前缀/后缀分拆重建每位候选的名次分布，并逐场核对首选集合。[评分与成本](../experiments/posterior-ranking-v1/summary.json) · [独立重建](../experiments/posterior-ranking-v1/verification/receipt.json)

**二、只在 C0 并列首选时，利用已有的比较理由。** 问一个可以用固定记录回答的问题：理由里最后一个可解析的候选下标，与返回的最终赢家相反时，这一票的信息是否足以帮助挑出更好的代码？只看已经问过的对局，把这种不一致当作可能较弱的一票；在并列者中优先选择较少依赖这种胜票、或遭受过这种负票的候选。对照是在同一场保留相同数量的标记，随机放到已采纳的票上。统计实际覆盖了多少场、改对/改错多少、对最终损失和时间的影响。从独立存档只提取已问边的标记，排除执行标签和未查询对。这个信号只利用有显式下标的文本；“提到过另一选项”和“最终判断有错”的关系需要实验验证。[来源映射与文本完整性](../experiments/selection-frontier-02/direction-audit/README.md)

这条破同分规则已经跑完。DeepSeek 实际采纳过的 3,349 个唯一候选对中，1,986 对可提取明确下标，仅 3 对前后方向冲突。850 场中 C0 有 243 场并列，规则只改变其中 1 场。任务等权损失改善 0.00046，95% 区间 [0, 0.00138]，最佳命中率持平。三份 GPT 记录在采纳过的比较中均无这种可提取的理由下标，2,550 场选择全部相同。该对照复用了自然语言材料中的一种格式信号，它只表明按显式下标破同分的触发面过窄。整次离线提取和评价约 8.48 秒墙钟，含文件读取和对照，新增模型调用与候选执行均为零。[实验与复核](../experiments/rationale-tiebreak-v1/README.md) · [原始统计](../experiments/rationale-tiebreak-v1/summary.json)

**已撤下的后续设想（未执行）。** 同一置信度下，文字理由对代码的可核实描述，能否帮助分辨哪些票更可信？例如“B 用了交叉验证”可以与实际划分/训练调用对照。先冻结一类跨任务可核实的事实以及处理“未知”的方式；将已问比较的理由与代码按候选身份对齐，单独处理转述或否定语境。用纯 CPU 的检查器提取标记，当源码证据或断言不明确时回退。先按任务留出比较“置信度”“置信度加事实标记”“同一置信度档打乱标记”，量出能覆盖的场数、正确性预测增量和运行成本。对已触发场用真实效用仅在评价端计算即使总能选对的收益上限；若上限已低于既有 0.01 尺度，或标记在留出任务中没有增量，就结束这条路线。只有信息值得用，才在同一 C0 轨迹上检验是否降低最终选择损失。该设计借鉴对解释事实根据的事后校准；原文实验来自 NLP 任务。有关 ML 代码上的效用与泛化仍是待验假设。[Ye 与 Durrett，NeurIPS 2022](https://papers.neurips.cc/paper_files/paper/2022/hash/c402501846f9fe03e2cac015b3f0e6b1-Abstract-Conference.html)

**如何看性价比。** 离线比较已付出的推理预算逐场对齐，新增费用来自选择器自身；预先比较相同预算下的终选损失、最佳命中率、CPU 耗时。一个方案工作起来很便宜，只有在同时选得更好或达到相同效用更省资源时才值得采用。任务间分数尺度不同，归一化损失差没有固定的人民币/秒换算。当前结果评价候选选择，在线完整 Agent 的时间和账单另需共同预算的实测。
