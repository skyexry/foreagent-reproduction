# 方案卡｜同一决策点，多问哪一对值得？

**状态：比较分配方向的候选方案。若选择这个方向，先做 D1，回读既有轨迹；D2 和全程策略只在前一步提供相应证据时进入下一轮。** 保留 C0 作整套选择过程的参考。下列门槛是建议预先登记的开发决策规则，本轮没有计算新策略成绩。

## 研究问题与假设

一次追加查询可能推翻当前首选。能使首选改变的查询，既可能纠正错误，也可能把好的程序换成差的。旧先导最大化两种假设胜负所对应的首选分布距离（TV），然后依次偏好触及首选、两端有效度数较少的边，最后随机破平。该规则没有给「无有效胜者」分支概率，也没有给换对、换错的执行代价赋值。已知其与同汇总随机补问的全程损失差区间跨零。**值得检验的是这种目标差异是否实际影响选择。** [旧策略 L7–74](../../reproduction/clean_ranking_v1/ranking.py) · [配对结果](../../experiments/clean-ranking-v1/results/summary.json)

- **H1，诊断。** 在相同起始信息、再问一次的条件下，旧主动策略比全边随机更容易发生代价大的错改，以致其平均净效用较弱。更高翻转率、更多弃权、较低的边准确率分别只是解释线索；H1 的主要证据是终局执行损失差。
- **H2，条件方法。** 若 D1 把问题定位到第一条补问，测试「先确定当前要验证的首选，再给它一个随机的未问对手」。当前首选与最终决策最直接相关；随机选对手减少规则反复挑特定类型对手的机会。也可能让偶然领先者靠弱对手累积优势，或漏掉尚无有效胜场的好代码。这一反例决定了同首选强对手与全边随机两个必要对照。
- **文献连接。** 信息价值给出衡量目标，冠军–挑战者提供分配结构，均匀对手提供可解释参照，三者各负责一个环节。原理论假设、领域实验和本项目的观察边界见[文献比较](literature.md)。这里没有拟合效用后验；“实际改选价值”由评分端的执行成绩定义。
- **修复与贡献。** C0 已处理缓存方向和结果绑定。此处各臂共用这些修复，比较的是其上的决策机制。主动 top-k、随机对手、执行 regret、离线矩阵回放均有先例；本项目可检验的增量是，在昂贵 ML 候选执行、比较可能弃权的设置中，哪次询问导致何种质量改变。能否据此形成可推广的方法，取决于后续结果。

## D1｜只用已保存的两条分支

**输入。** 读取 [850 个 jobs](../../experiments/clean-ranking-v1/prepared/jobs.jsonl) 和 [3,400 条历史选择记录](../../experiments/clean-ranking-v1/results/decisions.jsonl.gz)。仅取 `coverage_decision_sensitive` 与 `coverage_random` 两臂，按 `job_id` 配对。每场 n 个候选的随机链有 n−1 条**已问**边，其中可以有弃权，实际有效图可以断开。本轮只核对了输入结构和每场完整前缀一致，D1 的效用评分留待审阅后。

| 同一场的分支 | 唯一查询总数 | 识别的比较 |
|---|---:|---|
| S，共同链后就停 | n−1 | 基准首选及其并列分布 |
| U，读已存的随机下一边再停 | n | 相对 S，全边随机追加一问的实现价值 |
| T，读已存的旧主动下一边再停 | n | 相对 S，敏感性规则追加一问的实现价值；**T−U 为唯一主比较** |

1. **先封存决定。** 核验 v1 哈希和原决策文件 SHA-256（`e16781ad…98040ef`）；历史记录每行已带原终局的 metrics。抽取器对记录只投影 job_id、method、trace，对 trace 只投影端点、winner、confidence、来源索引；评分标签和原 metrics 留在评分/核验端。用 job_id 从 jobs 取得 seed 和原候选顺序，重建随机 shuffle 的相邻链；逐场校验它与两臂前 n−1 条记录的端点一致、两臂的 winner、confidence、来源索引相同，第 n 条为合法未问边。独立重建 S/U/T 三个首选集合，每个用相同的 `top_set`；先保存 `job_id, branch, edges, valid, selected, counts` 及哈希，然后评分端再读标签。两条下一边碰巧相同时仍纳入全部统计。[轨迹核验收据](../../experiments/clean-ranking-v1/results/verification.json) · [既有选择与独立评分实现](../../reproduction/research_env_v1/core.py)
2. **只在评分侧给效用。** 设某池执行成绩已统一方向，最好减最差为范围。对每个首选计算「池内最好减该项」除以范围，并列首选取均值，范围为零记损失0。记分支损失为 R。主比较 `R(T)−R(U)`，正值表示 T 较弱。另报 `G(T)=R(S)−R(T)` 与 `G(U)=R(S)−R(U)`，正值表示这一次询问值得。主要效用按池内范围解释；极窄范围可能放大微小执行差别，附逐任务原单位分差和池内跨度作敏感性说明。[正式评分 L68–109](../../reproduction/clean_ranking_v1/run.py)
3. **解释方向和幅度。** 分别累计纠正的效用 `mean(max(G,0))` 与错改的损失 `mean(max(−G,0))`，二者相减应精确回到平均 G。进一步令 D_harm=错改损失(T)−错改损失(U)，D_missed=纠正收益(U)−纠正收益(T)。按同样的任务等权计算，则 R(T)−R(U)=D_harm+D_missed。由此区分主动策略「换错了更多」与「纠正得更少」两种解释。再按首选集合维持/改变、有效/弃权、相同/不同下一边分解，并报告查询触及链后首选的比例、对手有效度数和全体样本分母。正确的单边判决也可能导致更差的最终选择。弃权消耗一次查询且首选应与 S 相同。错改定义按效用下降，两个集合不同但平均效用一致计为零。
4. **统计单位。** 对同一 job 算差，各任务内平均，再对全部26任务等权；重采样单位为整项任务，沿用10,000次、种子20261108093的成对任务簇 percentile 区间。同步报逐任务差/池数、改善/持平/恶化、最佳命中率（并列按均匀选择）、唯一读取、缓存、失败。逐一留一任务与所有小池分层仅作敏感性。两次种子不是独立语料；区间只反映该开发任务集的任务组成波动，裁判重采样、训练重复和新任务漂移需要另外估计。[锁定口径](../../experiments/clean-ranking-v1/protocol.json)
5. **诊断交付与成本。** 预期 850×3 个派生首选、26行配对汇总及错改分解。D1 在离线分析侧重读已有反馈；系统会计中每场 S/U/T 的逻辑查询数分别是 n−1/n/n，物理新增 API、训练、GPU 为0。一个本机 CPU 分析作业，建议墙钟上限10分钟（一项设计上限）；可先用三个场次核对接口，然后一次读完全部场次。封存派生选择后，在独立核验端先用完整历史分支重现原保存首选及各任务汇总，再计入新的前缀分数。缺轨迹、前缀/哈希不符即停止并保留失败记录；完整分母与故障记录一并保留。[先导核验](../../experiments/clean-ranking-v1/results/verification.json)

**D1 能回答的范围。** 三臂使用同一状态，主比较涉及旧 TV、触及首选优先级与破平等整套选边选择。分离 TV 与对手构成需要 D2 的同焦点对照。第 n 条之后两臂可能走入不同状态；多轮累积损失需全程配对验证。全部 850 场都有第 n 条边；其中840场 n=10，读完链后剩4次预算。另4场 n=3，链后只有一条边，提供了两臂必须给出同一结果的自然核验。

## D2｜条件策略：给当前首选安排哪一个对手

**先固定焦点，再随机选对手。** 完全复用 D1 的链 H。以 host 一致的胜率/有效度数得到并列首选集合，限于还有未问对手的首选，从中用 job seed 派生的伪随机序均匀选一个焦点 a。三条同焦点策略使用同一 a、同一未问邻居集 J、同一独立均匀对手排列。ID 只参与集合相等、可重复枚举与随机破平，策略不跨场存储。若所有首选均无未问对手、其余仍有边，三臂共用同一个全边均匀回退；无边则共停。单对手、回退和多对手场次分别列出，主表保留全部场次。

| 一步对照 | 从同一个 J 选谁 | 可辨识的作用 |
|---|---|---|
| **A，首选＋随机挑战（候选方法）** | 取共享随机排列首项 | A 对 U 检验“围绕首选取边”的整条规则；A 对 S 衡量多花一次查询的价值 |
| AT，首选＋敏感对手 | 取使 a 胜或负两种假设下首选分布 TV 最大的对手；若同分，取共享随机排列中最先者 | AT 对 A 固定 a、J 和破平，仅改敏感度打分。这里刻意去掉旧策略的度数等二级偏好；旧 T 另列 |
| AB，首选＋当前最强可挑战对手 | 取 J 中按同一胜率/有效度数排序最高者，再用共享排列破平 | 朴素而有竞争力的定向挑战。检验是否只需盯住最强竞争者，省去 TV 计算 |

**预测。** 相对于 U，A 将更多查询分配给当前首选；若主要误差来自首选仅凭很少的有效胜场领先，A 应降低一步 regret，且相对就停的平均执行效用也应提高。相反，若损失主要来自遗漏尚未进入首选集合的优质代码，盯住首选的优势应减弱。AT、AB 的表现决定“随机对手”是否值得保留。A 对 U 也改变了可选边和焦点分布，只能归因于规则整体；AT 对 A 才是同焦点的对手选择消融。A 与 AB 平手时优先简单规则；质量等效需区间落入预定等效界。

**门槛与转向。** 建议把 `δ=0.01`（一个池内效用范围的1%）作为是否值得继续投入的开发筛选尺度。该数是待审的研究决策，不代表测量误差、线上价值或已测出的最小效应。审阅时可按课程/资源价值改定一次，在读取 D1 新分数前锁定。各比较均以差值、区间和逐任务贡献呈现；除 D1 的 T−U、D2 的 A−U 外，其余为解释性比较。按阶段报告，避免在许多分支中选出最有利的一项。

- **进入 D2。** 在下述就停与任务敏感性检查后，仅在三个条件同时成立时登记一次 D2：全体 T−U>0，每个留一任务的 T−U 都>0，并且 D_harm>0 且 D_harm≥D_missed。最后一项把“错改”限定为至少与“少纠正”同样大的损失来源。达到这三项而主区间仍跨零时，D2 只作预设的一次开发探针。其他结果结束该 H1→H2 分支，记录较吻合的替代解释。
- **若 D1 的两种补问平均改善 G 都小于0**，且两者改善的95%任务簇区间上端均小于 δ，先结束当前的一步增益方向。下一轮可提交同一固定查询序列的预设前缀质量–成本曲线；允许自适应停的条件必须只依赖可见历史。看完标签再挑最优步数仅是 oracle 参照。
- **若 D1 第一问有益、效果只在后续反转**，先按已有轨迹定位后续损失首次累积的阶段。两个原臂后续历史通常已不同，需要在预先选定的一条参考轨迹的相同前缀重新分叉。若单个任务改变均值方向，优先记录其可问边、弃权与池宽，保留26任务主分析，暂缓增加策略。
- **进入全程开发验证。** D2 按以下顺序作决定。① 若 A 相对 U 与 S 的改善区间上端均小于 δ，结束“有实际价值的锚定随机增益”方向。② 若 AT 或 AB 任一臂平均损失比 A 低至少 δ，结束 A，以新假设另审。③ 仅在四项同时满足时进入全程：主差 A−U≤−δ、A−S<0、A 的平均损失不高于 AT 和 AB、每个留一任务的 A−U 均<0。④ 其余情况保留 C0。方向和精度分开报告；开发筛选通过支持提交下一步建议，新任务确认另立协议。
- **转向汇总或裁判。** 若正确的新判断频繁引起反向的执行损失，先在**相同已揭示边**上只换汇总作独立诊断；有效反馈本身经常与执行逆序时，才提出替换裁判或双序真判断。两类解释可能并存，须用“相同边换汇总”与“相同查询换裁判”分别鉴别。

若多个条件同时满足，优先检查“两种补问均弱于就停”，其次检查单任务影响和后续路径，最后决定是否进入 D2。若 D1 显示 T 的净收益明显优于 U，记录与 H1 相反的证据；若留一任务会改变均值差方向且区间较宽，保留 C0 并结束本轮开发判断。每次转向都保留原预测及负结果。

| 也许只是池构成、seed、拒判、错误反馈或分母在驱动？ | 逐场匹配、同汇总/同查询数、错误与正确改选分解、全体场次计费、任务簇与留一检查共同应对。观察到的中介分层按相关性解释；如少数任务驱动，需新状态分叉证据 | 影响效应解释及升级，D1 可做 |
| 提示、模型、数据质量足以支持判断吗？ | 记录快照、判断温度 T=1.0、报告/代码与单次原反馈。运行时只可看有效胜者与已问 confidence。原语料近重复、近等分数及运行随机性影响真值；需重复执行或独立评价器确认小分差。真正识别位置效应需相同代码双序新判断 | 对固定银行诊断可用；阻碍对潜在真实质量、独立模型随机性及去偏的外推 |
| 数据与实际效用之间差多远？ | 开发任务、完整反馈池、历史执行分数是条件总体；筛出的候选未必与在线同父新代码同分布。离线唯一读取、token、墙钟、GPU时间、最终提交成绩是不同指标。在线要绑定真实验证预测/节点与执行成本、确认生成脚本隔离；新任务必须在方法冻结后获取 | D1 可做。制约“新任务更准”“实际节省费用”“改善 Agent”等结论 |
| 检验失败是否还有贡献？ | 若就停已经表现合理，可给出额外询问造成错改的任务、状态和损失量级；若区间宽，给出能排除与仍容许的效应范围。能重复到新任务或另一份独立判断的效用规律，才具有外部实证价值 | 结果可支持基线合理；届时据证据结束、转向效率或另立研究 |
