# 模块卡与固定评测口径

机器配置：[registry.json](registry.json)。验收状态：[state.json](state.json)。本版本先固定“决定比较谁、何时停止”的接口。

| 模块 | 输入 → 输出 | 当前实现与目的 | 修改接口 / 验证 |
|---|---|---|---|
| 候选池 | 冻结代码代表 → 每场候选 ID 列表 | 26 任务、425 池、2 次重复，共 850 场；每池最多 10 份代码 | 固定 `prepared/jobs.jsonl` 与来源哈希；每池所有两两边均有记录 |
| 两两判断 | 查询候选 A/B → 胜者、confidence、有效性 | 作者固定 DeepSeek 判断；confidence≥0.7 且返回格式有效才有胜者 | 固定反馈；由 host 读取；反向查询映射回同一候选身份 |
| **比较分配 / 早停** | 候选 ID、已见反馈、剩余预算 → `compare` 或 `stop` | 策略决定下一对；示例为随机查询，用于验收接口 | **修改 `research/policies/*.py`**；每场独立进程，通过统一 CLI 评价 |
| 汇总 / 选择 | 已查询的有效比较 → 并列首选集合 | `clean_ranking_v1.ranking.top_set`：胜率优先、有效不同对手数其次、保留并列 | 本版本固定；改变汇总规则时登记新版本，单独区分分配收益与汇总收益 |
| C0 参考 | 同候选、同反馈、同上限 → 原淘汰赛首选 | 已修正正确性问题的原版 ForeAgent 排序，保留原配对/复赛/停止 | 可信 host 独立运行；逐场对齐 clean-ranking-v1 已存结果 |
| 评价 | 已保存选择 + 作者执行标签 → 损失 / 命中 / 成本 | 全部选择完成后，独立重建轨迹、再读取执行标签 | 固定评分与汇总；`evaluate --run …` 重算一致才通过 |
| 候选真实执行 / 在线 Agent | 代码与训练预算 → 验证预测 / 最终提交 | C0 短训练和受控链路已有证据；本接口使用现成反馈与标签 | 真实 API、完整脚本隔离、候选验证预测合约另行验收 |

## Environment：策略能做什么

`decide(observation)` 接收以下 JSON 字段：

| 字段 | 含义 |
|---|---|
| `episode` | 场次标识的哈希 |
| `candidates` | 当前候选 ID；与冻结候选一一对应 |
| `seed` | 本场固定随机种子 |
| `feedback` | 已查询的唯一比较，含 `a,b,winner,confidence,valid` |
| `remaining_budget` | 还能读取几条新的比较记录 |
| `attempts` | 已提交动作次数，含重复查询 |

返回 `{"action":"compare","pair":["id_a","id_b"]}` 或 `{"action":"stop"}`。策略只有选择对局和早停的权限。达到预算后 host 自动收尾。

反馈固定在作者的一次历史判断。重复查询同一对（含左右反转）得到同一条证据，只增加缓存读取/动作计数。低 confidence 也消耗一次唯一查询；本版本评估“如何使用同一批判断”，后续新判断模型或重复采样另建协议。

每场预算取冻结 job 的 `budget`，上限 13；动作最多 1,024 次。每次响应最多 2 秒、单场最多 6 秒、worker CPU 最多 2 秒；整次选择最多 600 秒。额度和评分由策略进程外的 host 执行。当前运行环境为 macOS + `sandbox-exec` + Python 3.12 标准库；策略工作目录独立，项目内容读取、外部写入及网络受操作系统限制。

候选 ID/seed 属于开发输入，代码作者可能已了解该语料；这套运行隔离验证的是**运行时可见信息与预算**。未来自动写代码的研究代理还需要单独的工作区隔离和全局实验预算，新任务确认集承担泛化检验。

## Evals：怎样判断选择质量

- **主指标 selection regret（越低越好）**：把同池最差执行成绩记为 0、最好记为 1；选择损失为“最好效用 − 所选效用”。先在每任务内平均，再让 26 个任务各占一票。并列首选按均匀随机选择的期望评分；同池效用全相同时，有效选择损失为 0。
- **最佳命中率（越高越好）**：并列首选中真正最好候选的比例，按相同的任务平均方式汇总。
- **成本**：唯一反馈读取、缓存读取、预算拒绝；另存 host 运行时间。这里的反馈读取次数是代理成本，真实 API 费用需要新实验测量。
- **差值与区间**：新策略减 C0；损失差小于 0 表示新策略较好。沿用固定任务簇 bootstrap、种子与重复次数。重复 seed 和重叠池保留在任务簇内。
- **失败**：每场保留在原定总数中，损失惩罚 1、命中 0，同时报告失败率与有效场次的场次平均损失。有效场次均值属于诊断指标，主结果仍按任务等权。
- **缺边与样本范围**：直接复用已验收的完整反馈池。Petfinder 和小候选池均保留；出现新缺边或输入变化时停止核验，先登记新协议再生成新池。

全部 26 任务都已用于查看与开发。当前结果支持固定反馈下的开发诊断；方法冻结后再设计新任务确认与在线端到端验证。

## 公平比较与版本规则

新策略与 C0 共用候选、历史反馈、阈值、每场预算上限、评价标签和统计口径。C0 按原规则停止，可能用得更少，因此同时报告查询数；后续若提出效率收益，应增加等质量/等成本曲线并登记协议。

当前策略采用固定胜率汇总，C0 采用原淘汰赛。因此“新策略 vs C0”反映整套选择过程的差异；若要归因于**比较分配**，同时与同汇总规则的 `example_random.py` 对照。原试验中主动分配的负面先导保持原记录。

`research/protected_manifest.json` 绑定可信实现、配置、标签、来源、旧基线及输出。新策略另存文件、每次运行保存策略快照和哈希，选择与评分分目录保存。修改可信规则时建立环境新版本；历史运行继续依其原版本解释。
