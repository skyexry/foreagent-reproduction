\section{Introduction}

Search-based machine-learning (ML) agents frame ML engineering tasks as a search over executable candidate programs. Each program embodies choices about data processing, model architecture, and training configuration. The agent proposes a program, runs it, inspects the resulting feedback, and uses that evidence to guide subsequent revisions \citep{jiang2025aide}.

Execution gives the agent evidence about a candidate: errors reveal implementation failures, while validation scores indicate its measured performance. In AIDE, this feedback guides the expansion of a tree of candidate programs \citep{jiang2025aide}. Obtaining that evidence can require hours of model training and evaluation \citep[Section~2.2]{zheng2026predict}. With limited GPU and wall-clock time, an agent can test only a fraction of its proposed programs; time spent on candidates later discarded leaves fewer opportunities to explore other ideas.

ForeAgent reduces this cost by using an LLM to compare candidate revisions before execution. Within AIDE's improvement stage, its Predict-then-Verify loop proposes multiple programs, predicts their relative performance through pairwise judgments, and executes selected candidates. Across five MLE-bench tasks, the authors report 3.2 times as many explored nodes, a 6-fold speedup in reaching peak performance, and an approximately 6\% relative gain in average Beat Ratio over AIDE \citep[Section~6]{zheng2026predict}. The benefit depends on reliable predictions: on the paper's pairwise corpus, its DeepSeek-V3.2-Thinking judge selects the execution-labeled winner in 61.5\% of comparisons \citep[Table~2]{zheng2026predict}. Such errors can remove promising revisions before verification, although this offline accuracy does not directly measure the online pruning error rate. More recent work, ForeCritic, trains a pairwise reward model with cross-entropy on winners determined by executed test scores and replaces ForeAgent's LLM judge within the same confidence-gated tournament \citep[Sections~4.2--4.3]{lee2026forecritic}.

These outcome labels identify the better completed program; they leave the quality of the intervening modification implicit. AdaPRA provides evidence that rubric-guided inspection of trajectories and workspace artifacts can expose process errors, including unsound validation and information leakage \citep[Section~3.4]{naik2026adapra}. This project asks whether explicit supervision of revision quality can improve candidate selection beyond outcome supervision, and thereby improve final ML performance under the same GPU and wall-clock budget. The process unit is a proposed parent-to-child code revision, assessed before the child is executed. A controlled comparison will give both selectors the same task, data report, parent code and observed feedback, and candidate revisions, so that extra context is separated from the contribution of process labels. ForeCritic motivates the outcome-supervised comparison; ForeAgent's generator, search tree, and execution rules remain fixed. Scoring time will count toward the common search budget.
