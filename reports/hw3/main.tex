\section{Introduction}

Search-based machine-learning (ML) agents frame ML engineering tasks as a search over executable candidate programs. Each program embodies choices about data processing, model architecture, and training configuration. The agent proposes a program, runs it, inspects the resulting feedback, and uses that evidence to guide subsequent revisions \citep{jiang2025aide}.

Execution reveals implementation errors and measures a candidate's validation performance. In AIDE, this feedback guides the expansion of a tree of candidate programs \citep{jiang2025aide}. Obtaining it can require hours of model training and evaluation \citep[Section~2.2]{zheng2026predict}. Under fixed GPU and wall-clock budgets, the cost of each run limits how many ideas the agent can explore.

ForeAgent reduces execution cost by using an LLM to compare candidate revisions before running them. Its Predict-then-Verify loop extends AIDE's improvement stage by generating multiple programs, judging their relative performance in pairs, and executing selected candidates. Across five MLE-bench tasks, the authors report 3.2 times as many explored nodes, a 6-fold speedup in reaching peak performance, and an approximately 6\% relative gain in average Beat Ratio over AIDE \citep[Section~6]{zheng2026predict}. These gains depend on prediction quality. On the paper's pairwise corpus, the DeepSeek-V3.2-Thinking judge selects the execution-labeled winner in 61.5\% of comparisons \citep[Table~2]{zheng2026predict}. An incorrect judgment can discard a promising revision before verification. ForeCritic addresses judgment quality by training a pairwise reward model with cross-entropy on winners determined by executed test scores. It replaces ForeAgent's LLM judge within the same confidence-gated tournament \citep[Sections~4.2--4.3]{lee2026forecritic}.

Outcome supervision identifies the better-performing program, while process supervision evaluates the quality of the proposed code revision. AdaPRA shows how rubric-guided inspection of trajectories and workspace artifacts can expose process errors, including unsound validation and information leakage \citep[Section~3.4]{naik2026adapra}. This project asks whether supervision of revision quality can improve candidate selection beyond outcome supervision and yield better final ML performance under the same GPU and wall-clock budget. The process unit is a proposed parent-to-child code revision, assessed before the child is executed. Both selectors will receive the same task, data report, parent code and observed feedback, and candidate revisions. This comparison isolates the contribution of process labels from that of additional context. ForeCritic serves as the outcome-supervision reference, and ForeAgent supplies the search and execution framework. Scoring time will count toward the common search budget.
