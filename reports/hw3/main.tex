\section{Introduction}

LLM-based machine learning (ML) agents automate model development by searching over candidate solutions through iterative cycles of code generation, execution, and refinement. Candidate evaluation requires training and validation, which can make broad exploration computationally expensive \citep{jiang2025aide,zheng2026predict}. Generation and predictive comparison also consume resources, and their cost relative to execution depends on the task and deployment. Together, these costs limit how many experiments an agent can run within a fixed budget, making search decisions consequential for both resource efficiency and final performance. Poor decisions are costly in two ways. In terms of efficiency, repeated failures and revisions that bring only marginal gains consume time and compute, delaying progress toward a target level of performance. In terms of solution quality, fixating on a narrow family of approaches or continuing to refine a stalled solution can keep the agent from finding stronger alternatives before its budget runs out. These challenges raise a broader question: how can ML agents learn from past experiments to improve how they generate candidates, assess alternatives, and choose subsequent search directions?

AIDE \citep{jiang2025aide} structures this search as a tree whose nodes contain candidate programs and their execution results. Drafting, debugging, and improvement operators expand the tree, while a search policy determines which node to develop next. Summaries of previous attempts provide context for subsequent code generation, allowing the agent to build on promising solutions and repair unsuccessful attempts. However, each new candidate must be executed before its measured performance can inform further search. Consequently, the cost of training and validation constrains how broadly the agent can explore.

ForeAgent \citep{zheng2026predict} builds directly on AIDE's architecture and addresses this bottleneck by redesigning the improvement stage. It generates multiple candidate solutions and uses an LLM to compare their expected performance based on their code, the task description, and a verified data analysis report. Confidence-gated comparisons filter the candidates before selected solutions are executed. This \emph{predict-then-verify} workflow allows the agent to consider more alternatives without training every candidate, while retaining real execution feedback to verify progress. In the authors' evaluation on five MLE-bench tasks \citep{chan2024mle}, ForeAgent explored more candidates and reached peak performance faster than AIDE. These results demonstrate the promise of predictive selection for improving search efficiency.

Subsequent work seeks more informative and reliable evidence for predictive decisions. MLE-World \citep{ko2026mleworld} predicts execution outputs, including errors, training logs, and validation scores, and uses them to support both candidate selection and code revision. Its pairwise selection strategy extends ForeAgent by incorporating predicted terminal outputs into candidate comparisons. ForeCritic \citep{lee2026forecritic} takes a training-based approach, learning preferences from executed program pairs to directly predict which candidate will perform better. The authors evaluate this selector within AIDE, ML-Master, and ForeAgent. Rehearse \citep{ji2026rehearse} instead retrieves similar modifications and their observed outcomes from the current task to inform comparisons between new proposals, then adds subsequent execution results to its memory. These methods ground selection in predicted execution feedback, outcome-supervised preferences, or relevant historical evidence. Rehearse augments a prescribed comparison procedure with retrieved cases, while ForeCritic trains the selector. This proposal extends the focus to experience-driven revision of the surrounding generation, comparison, and resource-allocation procedures.

A separate line of work makes the agent's own operating procedures a target for improvement. Inspired by recursive self-improvement (RSI), \emph{harness evolution} updates the prompts, reusable skills, memory mechanisms, and control logic surrounding an LLM. AIDE$^2$ \citep{srikanth2026aide2} implements an outer optimization loop that modifies a research agent's code, evaluates the resulting versions on a task suite, and retains changes that improve performance under fixed evaluation budgets. Its discovered modifications include search policies and context-management mechanisms. Evo-Harness \citep{wei2026evoharness} instead adapts through reusable guidance: it converts execution experience into skills and updates the external harness across tasks while keeping the underlying model frozen. These studies provide empirical support for improving agent behavior through changes to its harness.

Applying harness evolution to predictive search introduces a specific challenge: candidate generation, predictive selection, and execution feedback jointly determine which experiments the agent observes and learns from. Changes to the generator alter the candidates presented to the selector, while changes to the selector alter which candidates receive execution feedback. An improvement to any individual component must therefore be evaluated by its effect on the full search process. AIDE$^2$ evolves an AIDE-based search driven by execution feedback; its reported design does not include ForeAgent's pre-execution predictive filter \citep[Sections~2.2 and~3.5]{srikanth2026aide2}. ForeAgent introduces this additional selection stage while retaining predefined comparison prompts and selection rules \citep{zheng2026predict,foreagentcode}. This makes ForeAgent a natural testbed for studying how experience-driven updates to the harness affect both the quality of search decisions and the resources required to make them.

This proposal therefore asks: \textbf{Can harness evolution make machine learning agents search more efficiently?} Using ForeAgent as the baseline, the following sections explain its predict-then-verify workflow and present a reproduction that includes candidate generation, experiment selection, and actual model training and validation. The end-to-end run provides the foundation for studying adaptations to individual components and their interactions. Planned evaluations will assess whether evolved harnesses find better solutions within a fixed total budget or reach comparable solution quality with fewer resources, with the cost of harness adaptation counted toward the total budget.
