## 2. 五秒级训练怎样做

首轮限定 Stanford，选本次已保存且有效执行过的三个真实候选。候选模型及其处理函数先静态审阅，短跑入口沿用实际路径；适配只涉及输入子集、步数/时间和输出位置，差异逐项记录。

| 代表候选 | 已确认的模型类别 | 覆盖重点 |
|---|---|---|
| `2310e6bf` | Transformer | 序列维度、padding/有效位置、注意力和输出形状 |
| `0cae1a47` | LSTM | 序列长度、预测位置、训练/验证损失计算 |
| `8dce0f8c` | CNN＋LSTM | 卷积维度、序列对齐、梯度与参数更新 |

- 从公开训练数据预先固定64条训练、32条验证及其ID；实际条数由各候选输入要求核对。固定两个seed，各候选使用同一划分。
- 每次运行目标为训练阶段约5秒，记录实际步数、样本数和单步时间；初始化、数据读取、验证与写预测分别计时。整进程建议60秒硬上限，超时单列诊断。
- 检查输入/输出形状、finite loss/梯度、优化器后参数变化、训练与验证模式切换；用独立函数重算验证指标，验证ID和mask对齐。
- 每份预测绑定候选ID、代码哈希、seed、划分和步数。按同一验证指标生成诊断排序，核对方向、并列与节点绑定。
- 训练5秒可能得到暂时不同的排序；该排序用于查计算、汇总与保存链路。正式架构优劣使用正式训练协议评价。

**资源方案：** 使用已存在的Python3.11/PyTorch2.2环境，CPU首轮、最多2线程；3候选×2seed，目标训练阶段合计约30秒，进程硬上限合计6分钟。入口适配与依赖检查约半天至一天；API与GPU租用预算为0。额外包安装、外部权重下载或GPU运行另列资源方案。

## 3. 怎样检查泄漏、虚报和结果残留

| 检查 | 操作与通过条件 |
|---|---|
| 标签访问边界 | 候选环境挂载公开训练数据及无标签测试特征，记录训练/验证划分与标签流向；优化器只使用训练部分。验证预测在独立进程复算，私有答案、已知测试成绩和审计记录置于候选运行环境之外。隔离执行时关闭网络，凭据与共享旧输出隔离 |
| 数据划分 | 检查训练/验证ID与序列重合，依据任务关系记录近似重复；预处理拟合范围和目标特征路径可追溯 |
| 真正训练 | 查看实际参数更新和新预测；独立重算指标，与日志报告逐项核对；打印分数与计算分数的一致性有证据 |
| 输出新鲜度 | 每次独立输出目录，故意安排“前一个候选写文件、后一个不写”的反例；节点身份与预测来源始终匹配 |
| 标签打乱控制 | 增加一轮小样本训练标签打乱检查，观察训练路径和验证统计的响应；若仍得到异常好分，追查标签/数据/指标路径。短跑样本的偶然波动单列 |
| 指标与排序控制 | 手工构造好/坏预测及不同文件排列，核对mask、指标方向、并列、筛选和最佳保存；无须依赖某种架构一定学得更快 |

将泄漏、作弊作为待检行为，以静态路径检查、运行隔离和可控反例取得证据。首轮通过说明上述候选及路径完成验收；其余任务/架构按后续研究范围扩展。

## 4. 与排序实验怎样衔接

1. C0正确性反例通过，记录每项修正的源码差异和影响。
2. 三类候选短跑及独立评分/产物绑定检查通过。
3. 受控裁判反馈跑通生成候选身份→比较→筛选→执行→反馈→最终保存的缩短链路，边界情况可追踪。
4. 冻结C0，开始离线比较分配先导。裁判固定，三种比较分配使用新写的同一胜率汇总，在同候选与新比较预算下比较随机、覆盖和主动补问。
5. 离线结果支持进一步研究后，另审阅实际LLM与端到端预算。公开Corpus测试标签用于评分，在线搜索使用当时可见的验证反馈。
