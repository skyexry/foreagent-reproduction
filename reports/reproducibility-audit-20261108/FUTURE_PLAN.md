C0反例、三架构×两seed约五秒训练、标签流向对照及真实Agent类受控集成已完成，见[短测试执行状态](./BASELINE_SHORT_TEST_PLAN.md)。短跑使用原模型/处理函数并以统一指标独立评分；完整生成/API端到端及任意候选脚本的操作系统隔离另作部署验收。

## 2. 第一项训练实验，具体做什么

**问题：用真实执行成绩训练裁判，能否比 ForeAgent 原来的通用 LLM 判断，更准确、更低成本地筛选值得运行的代码？** 任务隔离用于检验结果的适用范围。

先锁定一个按任务隔离的先导划分。可采用 18 个训练任务、4 个开发任务、4 个测试任务；开发任务再分用于选 checkpoint 与校准概率的互斥部分。任务名单依据领域、代码覆盖和候选数确定，并在训练前保存。相同内容与近似代码簇跨任务的情况单独排查。

训练输入为 ForeAgent 决策时可见的任务描述、报告和真实代码，标签为任务内真实执行成绩决定的胜者。先设计一个小规模成对判断模型：冻结编码器加选择头作为便宜控制，LoRA 加选择头作为训练候选。模型、最长输入和精度由输入需求、数据规模和硬件预检决定；按自己的训练配置完整记录。ForeCritic 的训练经验供参考。

测试时给每种方法同一批候选。优先在可形成共同候选池的任务使用固定 K=5；候选少于 5 的任务单列按实际 K 评价。先把规则锁定，再比较：

- 随机选一个候选，作为最低成本参照。
- **主要对照：ForeAgent 原 LLM 裁判与我们训练的裁判，接入同一固定筛选协议。** 先用已保存作者判断建立离线对照，再按所需共同输入明确复测预算。
- 固定 R7 汇总作为额外简单对照；用同一新池重算，缺反馈的情况另列。
- 初始化模型与训练后模型，检验监督训练本身带来的变化；新的随机选择头另外训练作控制。
- ForeCritic 权重若可取得，按同样测试池评估；其已知训练任务与代码重合情况一起披露。

保存的 LLM 判断按其原模型/输入版本标注；同一当前端点的复测另列调用预算。并列选择规则与随机 seed 在运行前固定，缺失响应同时报告计划分母和有效分母。

**主要看选错损失，次要看两两准确率。** 每个池的归一化损失定义为：(池中最佳效用－所选效用)/(池中最好－最差效用)，效用按任务方向转换为越大越好。全同分池损失记 0，并单列数量。同时报告最佳命中率、任务等权 pair accuracy、每任务结果、输入 token、延迟和显存。

现有 26 任务都参与过项目分析，所以这一项是回顾性开发研究中的“微调未见任务测试”。方法固定后的新任务另作前瞻确认。

## 4. 三个研究问题，按当前优先级排列

### 优先级 1：执行数据能否改善 ForeAgent 的方案判断？

**依据与意义：** 原 ForeAgent 审计 F07/F10/F11/F12，以及现有比较与动态执行记录。通用 LLM 判断、置信度和实际方案收益之间存在待解释的差距。用真实执行结果学习专门裁判，是直接从 ForeAgent 延伸的研究问题；任务隔离和重复内容处理保障评测可信。

**假设与机制：** 真实执行监督能让专门裁判比通用 LLM 更有效地利用任务与代码信息，改善 ForeAgent 的方案选择。先用普通偏好训练建立自己的学习基线，控制内容组、轨迹与任务采样权重，并检验任务迁移。

**最小实验与控制：** RM1 的一个划分，ForeAgent 原 LLM 与训练裁判使用同一候选池、同一筛选规则；初始化、随机及 R7 作控制。另报告熟悉任务的新代码对，检查代码长度/模型家族等简单特征、A/B交换、任务名称和数据报告的作用；训练格式覆盖与输入长度同时披露。

**怎样判断：** 任务隔离测试中损失下降且多数任务有一致方向，支持继续；收益集中于已见任务或模板时，研究任务适应与信息来源。不同划分的样本难度也会变化，下降幅度需结合匹配控制解释。

**新颖性、依赖与风险：** ForeCritic 已有迁移测试，系统验证先提供基线与可靠性价值。更广贡献取决于能否揭示失效机制并提出有效修正。依赖完整代码、划分、模型预检；26 任务和少量独立代码限制估计精度。参考 [ForeCritic](https://arxiv.org/html/2610.38439v1#A4)、[NAS 性能预测比较](https://arxiv.org/abs/2104.01177)。

### 优先级 2：怎样训练和使用裁判，才能让 ForeAgent 最后选得更好？

**依据与意义：** ForeAgent 的淘汰赛、多候选选择与已有 R7/R8 记录，以及原审计 F07/F08/F11。项目希望找到好方案，pair accuracy 是中间指标。需要区分判断能力、汇总规则和最终选择的作用。

**假设与机制：** 在同任务内，用经过尺度处理的真实分差给偏好损失加权，能降低最终选择损失。第二步再比较独立打分 r(任务,报告,代码) 与联合读 A/B 的比较器；独立分数便于排序，多候选的实际速度需测量。

**最小实验与控制：** 先保持模型与输入相同，只改普通交叉熵/分差加权这一项；比较最终 regret、命中率和 pair accuracy。有效后再单独改接口，控制初始化、训练 token、调参次数和候选池，保留等预算曲线。训练中的尺度和权重只由训练部分确定。

**怎样判断：** pair accuracy 相近、最终损失下降，是有价值的结果；提升被训练预算或重复代码解释时，优先保留简单方案。分差加权放大执行噪声时，转向稳健标签或重复执行诊断。

**新颖性、依赖与风险：** 加权排序和代码数值预测都有前人工作；贡献要来自对 ML Agent 决策目标的有效改进和机制证据。参考 [Regression Language Models for Code](https://proceedings.mlr.press/v306/akhauri26b.html)。依赖 RM1；真实成绩主要为单次观测，跨任务尺度与随机波动是主要风险。资源为一对匹配训练方案乘 3 seeds，按预检核算。

### 优先级 3：什么时候让真实执行纠正裁判？

**依据与意义：** ForeAgent 的置信度门控、复赛、真实执行与本项目已核验的验证—私有成绩差异（F06/F07/F10/F11）。便宜的裁判与可靠的执行各有价值。

**假设与机制：** 把不确定性、潜在选错损失和预计执行成本结合起来安排验证，能在同总预算下改善最终质量。先试固定比例执行与单阈值，再讨论更复杂的动态策略。

**最小实验与控制：** 先使用已有 journal 做开发诊断，补齐代码、验证指标、执行时长和失败类型；比较随机执行、固定阈值与成本感知路由。真实执行只回传当时可见的验证指标；私有成绩仅用于最后评估。跳过而未运行的代码单独标识，其反事实结果需要新执行才能取得。

**怎样判断：** 同质量时总成本更低，或同成本时质量更高，支持扩展；概率虽更准但执行后收益很小，则保留较简单策略。不同候选覆盖造成的变化需用共同池或随机探索控制。

**新颖性、依赖与风险：** ForeCritic 已提出对不确定判断做验证，固定阈值是已有思路。新增价值取决于损失、执行成本和新反馈的联合证据。参考 [ForeCritic §7/Impact](https://arxiv.org/html/2610.38439v1#S7)、[校准方法](https://proceedings.mlr.press/v70/guo17a.html)。依赖 RM1、可用的时间与验证标签、修正版执行链路；离线 replay 有选择偏差，线上预算另审阅。

## 5. 保持比较公平的几条具体规则

1. **真实标签与裁判意见分开。** 学执行成绩作为主要目标；若用 LLM 意见训练，单列为蒸馏实验。训练输入只包含决策时能看到的信息。
2. **先分任务/代码内容组，再生成比较对。** 同一代码或相近轨迹的身份与哈希写入清单，随机打散 pair 作为另一个诊断协议。
3. **在同一候选池评测。** 简单 R7 继续作汇总控制，比较器训练与比较分配分开改。样本覆盖、失败数与分母逐项报告。
4. **调参、校准和测试各有归属。** 相同数据访问和调参预算；test 用于已锁定方案的评估。主报任务等权结果、任务簇区间与种子波动。
5. **统一端到端协议。** 在线前处理 checkpoint 归属、提交隔离、缓存方向和评分器；同一生成器、候选预算、时间预算、排序与停止规则下先只换裁判；后续筛选/停止策略作为单独因素研究。
6. **成本全记账。** 分开记录训练/准备、推理、候选执行、失败重试和服务等待；同时给一次性成本与按使用次数摊销后的成本。新任务在线适应使用验证反馈，私有结果留到评估。

离线数据核查与训练先导可以先于全部 Agent 修正推进。在线比较依赖修正后的执行/评分链路。
