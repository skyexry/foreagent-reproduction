# ForeCritic：它怎么训练，你可以接着研究什么

**研究定位更新：** 本项目直接基于 ForeAgent 研究方案判断与筛选；本文是相关工作精读。ForeCritic 的实现核验和扩展属于可选工作，主线与第一项比较以当前 [Future Plan](./FUTURE_PLAN.md) 为准。

**我的建议：把“训练一个专门判断 ML 方案的 reward model”作为下一阶段候选主线，先检验它在新任务上选得怎样，再研究怎样减少选错的损失。** ForeCritic 提供了可借鉴的训练思路；你的新增证据应当落在泛化、最终选择质量和实际成本上。

本轮完成论文阅读与现有数据盘点。训练、模型请求、GPU 租用均为 0。具体执行顺序见 [Future Plan](./FUTURE_PLAN.md)。

**数据补齐更新：** 已从固定 revision 下载剩余 521 份代码，完整原始数据现有 895 份代码、878 种字节内容，覆盖全部 18,438 对比较。见[数据入口](../../data/reward-model/corpus-6b322cb-raw-v1/README.md)。原 374 份代码盘点作为历史证据保留；下文使用补齐后的数量。

## 1. 先理解它在做什么

假设 Agent 为同一个任务写了 A、B 两份代码。把它们都训练一遍，才知道谁好，会花很多时间。

ForeCritic 是一个提前筛选的裁判：读任务、数据报告和两份代码，直接给出“选 A/选 B”以及概率。训练时，答案来自已保存的真实执行成绩。这里学的是**方案之间的偏好**，可以先用于筛选；生成代码的 Agent 与强化学习训练属于后续系统选择。

一个关键区别：它的概率表示“A 比 B 好的可能性”。这个概率与 A 本身预计能拿多少分，是两种量。把不同对手下的胜率接进搜索树，需要明确汇总规则。

## 2. 具体怎样训练

下表来自 [§4、附录 C](https://arxiv.org/html/2610.38439v1#S4)，属于论文报告的配方，运行复核列入后续。

| 环节 | 配方与白话解释 |
|---|---|
| 初始化 | Kev-9B，底座 Qwen3.5-9B-Base；已有通用选择能力 |
| 输入与输出 | 任务、报告、完整代码 A/B；pointer head 直接给两个选项打分，一次前向读取，输出选择概率 |
| 标签与损失 | 真实 test score 决定胜者；交叉熵鼓励模型提高胜者的概率 |
| 数据划分 | 训练 5,000；选 checkpoint 250；校准概率 250；内部测试 500；最终测试 12,438 对 |
| 更新参数 | 冻结底座，更新 LoRA 与选择头；rank=16、alpha=32、dropout=.05，头维度 4,096→256 |
| 优化 | AdamW；adapter/head 学习率 1e-5/2e-5；weight decay=.01；clip=1；warmup=5%；余弦降至峰值的 10% |
| 数据增强 | 三种输入格式 × A/B 两种顺序；每个 epoch 每对随机呈现一种，共 4 epochs、628 updates |
| batch 与选择 | 有效 batch=32：8 GPU × microbatch 1 × accumulation 4；按验证准确率选 checkpoint，同分看 NLL |
| 校准与成本 | 独立校准集拟合 temperature；最长约 46K tokens，完整保留输入；8×A800、4.18h，约 33.4 GPUh |

“LoRA”可以理解为给大模型加一小组可训练的调节参数。“选择头”是把模型读到的信息转换成两项概率的小模块。“校准”是调整概率的刻度，例如让报出约 80% 把握的一组判断，其实际正确率接近 80%。这三项各有作用。

论文中的 ForeCritic 是**同时读两份代码的比较器**。我们先前讨论的“每份代码独立打分，再统一排序”，是另一种待比较的设计。

作者把它用于两种场景：ForeAgent 中替换 LLM 裁判；AIDE/ML-Master 中用比较结果代替搜索过程的大部分执行，最后再运行和修复提交代码。两类集成应分别评价。

## 3. 怎样看它的实验和核心结论

论文的表 1 报告：训练前后总体准确率 54.53%→79.44%，任务等权准确率为 72.69%；501 对双方代码均未参加训练的样本上为 71.46%。训练前后使用相同架构的对照，是本文较有说服力的部分。[Table 1](https://arxiv.org/html/2610.38439v1#S5.T1)

我的评价是：这些结果支持“执行成绩能教会专门裁判”，对“全新任务是否可靠”的证据还可继续扩充。主实验共享任务和部分代码；迁移实验已有覆盖，但规模小，而且仅包含被该模型参与筛选后真正执行的候选。完整问题和检查列在下一节。

理论部分讨论的是：给定同样的信息，理想的最优决策器有一个共同上限。它为直接学习决策提供理由；具体模型在有限数据、有限算力下谁更好，仍由实验判断。推理可能帮助有限模型接近上限，论文 §3.1 也明确说明这一点。附录 B 的候选数量推算依赖理想化分布和独立性，应当作为机制示例使用。

## 6. 我建议的研究重点

第一步先回答：**用真实成绩训练的小裁判，能否在微调未见的任务上，以较低推理成本选到更好的方案？** 这是整个研究的证据基础。它也帮助我们判断后面该改模型，还是改执行策略。

一个便宜的诊断是：同一 checkpoint 分别读取完整报告和省略报告的输入，观察任务隔离后报告的作用。ForeCritic 在主要测试中报告去掉报告准确率下降 0.89 个百分点、输入缩短 63.9%（§5.2）；它的训练增强本身包含省略报告的格式。这提供了效率线索，报告在新任务上的作用值得另外验证。

接下来最值得试的是“按选择损失训练”。例如，误选一个比最好方案差一点的候选，与误选一个差很多的候选，实际后果不同。可以先试任务内分差加权，再比较独立打分与成对比较。它们都是有既有方法基础的机制，研究价值需由严格对照下的结果和解释建立。

再往后是“有价值时真正执行”：一个便宜的候选即使判断有些犹豫，也可能值得跑；一个执行昂贵、潜在提升很小的候选，决策可能不同。ForeCritic 自身已建议对不确定判断执行验证，所以新增贡献要来自成本、潜在损失与新反馈如何共同改变决策的实证结果。

## 7. 文献定位与复现材料

- **ForeCritic**：Lee, Yang, Liu, Liu (2026)，*Predict the Reward, Not the World: World Reward Models for ML Agents*，[arXiv:2610.38439v1](https://arxiv.org/abs/2610.38439v1)。本轮读正文及附录 A–E、表 1–2 和图 1–11 的文字说明；训练与在线结果均按作者报告引用。来源 HTML 的 SHA-256、阅读覆盖与材料缺口见 [阅读核查](./evidence/forecritic-reading.json)。
- **ForeAgent**：[ACL 2026 原论文](https://aclanthology.org/2026.acl-long.182/)。当前公开偏好语料和固定实现来自它；代码版本 c4d52cf，语料版本 6b322cb。
- **初始化模型**：[Kev 1.0 发布页](https://github.com/jaredpalmer/kev/releases/tag/kev-1.0)。已核实存在 Kev-9B adapter/head 资产及版本元数据；这是初始化来源，ForeCritic 自身的训练产物仍待取得。
- **最接近的另一个方法来源**：Akhauri et al. (2026)，[Regression Language Models for Code，ICML，PMLR 306:1578–1601](https://proceedings.mlr.press/v306/akhauri26b.html)。已研究用语言模型预测代码执行数值。因此“每份代码输出一个分数”的基本形式已有相关工作；自由形式 ML 方案的跨任务选择质量是我们需要实测的区别。
- **比较性能与成本的背景**：White et al. (2021)，[How Powerful are Performance Predictors in Neural Architecture Search?](https://arxiv.org/abs/2104.01177)。说明训练准备成本、预测成本和排序能力应共同评价。该工作针对 NAS，迁移到本项目需检验。
- **校准方法**：Guo et al. (2017)，[On Calibration of Modern Neural Networks，ICML，PMLR 70:1321–1330](https://proceedings.mlr.press/v70/guo17a.html)。temperature scaling 是既有方法；换任务后的决策价值需要本项目自己的证据。
